# 修复：设置-组件页 侧边栏选中 ↔ 右侧目录 不同步

## 根因
`ComponentsSettingsPage`（`Sources/NotchCenter/SettingsPages.swift` 327–529 行）中，侧边栏高亮由 `selectedPluginID` 驱动，右侧内容由滚动位置决定，两者只有单向一次性的 `proxy.scrollTo` 同步；懒加载 + 变高行让 `scrollTo` 经常落在错误偏移。另有：滚动不回写高亮、重复点击同一行不回滚、初始/重建时选中态失配。与最近 988f0a8 拖拽驻留提交无关。

## 改动（仅 `SettingsPages.swift`，保留目录式右侧布局）

1. **保留 `LazyVStack` 与内层 `LazyVGrid`**：卡片是真实块预览，懒加载保留合理，不做 eager 化。
2. **滚动机制替换**：删掉 `ScrollViewReader` 包裹与旧 `onChange(of: selectedPluginID) { scrollTo }`（347–371 行），改为 `@State private var scrollPositionID: String?` + 右侧 `ScrollView` 挂 `.scrollPosition(id: $scrollPositionID)`（macOS 14+ API）。`scrollPosition` 按 ForEach 数据身份定位，对懒加载内容先实例化目标再锚定，比 `proxy.scrollTo` 可靠。同时移除 `groupSection` 上的显式 `.id(group.id)`（353 行）——与数据身份重复，且 `.id` 修饰会干扰懒加载复用与锚定。
3. **正向同步（点侧边栏 → 跳转）**：`pluginRow` 点击 → `selectedPluginID = group.id`，并 `withAnimation(.easeOut(duration: 0.2)) { scrollPositionID = group.id }`。程序化滚动动画期间（约 0.25s 抑制窗，Task 计时）暂停反向回写，避免高亮途经中间分区闪烁。
4. **反向同步（滚右侧 → 高亮跟随）**：`onChange(of: scrollPositionID)`：值非 nil、不等于当前 `selectedPluginID`、且不在抑制窗内 → 写 `selectedPluginID`。
5. **初始态**：`rebuildIfNeeded` 末尾若 `selectedPluginID == nil` 且 `groups` 非空 → 高亮第一组，但不动滚动位置（`scrollPositionID` 保持 nil），保住顶部拖拽提示条可见。
6. **重建兜底**：选中组消失（插件被关闭/卸载）时回退到第一组并同步 `scrollPositionID` 定位过去，替代现在的静默置 nil。
7. **重复点击同一行**：用户滚走后绑定已被滚动更新为其他分区，再次点击赋值即触发滚动，天然修复。

## 验证
- `swift build && swift test` 全绿（不新增单测：滚动同步是视图层行为，无可提取纯逻辑）。
- `./scripts/build.sh run` 真机验证（先杀旧实例）：点侧边栏精确落在分区顶（**重点**：跳到尚未实例化的远处分区是否准确锚顶，这是保留 LazyVStack 的唯一风险点）、滚动右侧高亮实时跟随、滚走后重复点击能回滚、首屏默认第一组高亮且提示条可见、开关插件后选中回退第一组、空目录不崩。
- 若真机发现懒加载落点偏差：备选为同点位 `LazyVStack` → `VStack`（一行改动）或 scrollTo 后二次校正，验证不通过不收尾。
- 新增注释遵守 `docs/TERMINOLOGY.md` 术语纪律；纯 bug 修复不改 docs。
