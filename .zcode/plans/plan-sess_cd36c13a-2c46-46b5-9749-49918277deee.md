# 块内"+"新建笔记：切换并聚焦被点击的块

## 根因

043ce21 引入的"外部入口标签跟随"逻辑（`NotebookBlockView.swift:96-110` 的 `onChange(of: store.tabs.map(\.id))`）与块内"+"路径存在时序竞态：

- "+"路径：`store.addTab()` → `onSelectTab` 改本地 `activeTabID` → 依赖 `onChange(of: activeTabID)`（L89）里**才**写 `rememberActiveTab`。
- 两个 onChange 在同一事务里的触发顺序不受 SwiftUI 保证；若"跟随"分支先触发，读到的是旧记忆值（≠ 新 activeTabID），把点击实例的选择**弹回旧笔记**——新笔记建了但没显示。
- 紧凑图标路径正常，因为 `createNoteInTopmostPlacement`（`NotesPlugin.swift:151`）在点击处理器里**同步**写记忆，任何 onChange 触发时读到的已是新值。

## 修改（全部在 Plugins/NotesPlugin/Sources/，共 2 个文件）

### 1. `TabPagerControl.swift` — 新建入口改为注入闭包

- 新增参数 `let onCreateNote: () -> UUID`。
- "+"按钮 action 中 `store.addTab()` 替换为 `onCreateNote()`（`rememberCurrentSelection()` 与 `withAnimation { onSelectTab(newTabID) }` 保持不变）。

### 2. `NotebookBlockView.swift` — 闭包内同步写记忆 + 挂起焦点

```swift
onCreateNote: {
    let newTabID = store.addTab()
    // 必须在任何 onChange 触发前同步写记忆（与紧凑入口 createNoteInTopmostPlacement
    // 的写序一致）：标签跟随 onChange 可能先于 activeTabID 的 onChange 触发，
    // 读到旧记忆会把本实例的选择弹回旧笔记。
    NotesModel.shared.rememberActiveTab(newTabID, for: placementID)
    // 新文档（documentId 变化）重建编辑器、bind 时自动聚焦——与紧凑入口同一机制。
    editorInteractionState.scheduleDeferredFocus()
    return newTabID
},
```

- `onSelectTab` 闭包（L52-58）保持不变，继续负责切本地 `activeTabID` + `restoreSelection`。
- 更新 L102-104 注释，说明新不变量：本地入口在改本地状态前已同步写记忆，跟随分支不再依赖 onChange 顺序。

## 明确不改

- 紧凑图标路径（`createNoteFromCompactIcon` / `createNoteInTopmostPlacement`：定向最上方实例 + 展开抽屉）。
- 状态栏菜单 "New Note"（同样走 topmost 路径）、设置界面按钮。
- `NotesStore` / `EditorInteractionState`（`focusEditor` 已有隐藏窗口防护 L219-222，deferred focus 走 bind 路径同样受 `bind()` 的可见性守卫保护，不会唤醒其他屏抽屉）。
- 多屏同 placement 的隐藏实例会经跟随逻辑同步 `activeTabID`，其 `requestFocus` 已被防护挡住——与紧凑路径现有行为一致。

## 验证

1. `swift build` && `swift test`（现有套件全绿；本次是视图接线改动，onChange 顺序本身无法单测捕获，修复正是让它与顺序无关）。
2. 手动回归（注意先杀旧实例再 `swift run`，避免旧进程干扰）：
   - 抽屉放两个笔记本块，点**下方**块"+"→ 该块切换到新笔记、光标可直接输入；上方块不动。
   - 单块场景：点"+"→ 切换 + 可直接打字。
   - 紧凑图标回归：仍切换最上方块并展开抽屉聚焦。
