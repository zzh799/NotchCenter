## 目标

设置页拖动最小/最大列数（及最小行数）后，抽屉的尺寸变化与块的重排用 spring 平滑过渡，而不是瞬间跳变：可见面板宽度 spring 收缩/舒展、越界重排的块平滑滑入新位置。

## 现状结论（探索确认）

- `rebuildContent(animated: true)` 已把 `drawerWindowSize`/`drawerElements`/`drawerGridLeftColumn`/`MinRows/MinColumns` 同批写进 `withAnimation(DrawerAnimation.spring)`；网格层已有 `.animation(value: placement)` 两条修饰符驱动块滑动——**块重排动画是现成机制，列数路径只是没传 `animated: true`**。
- 阻碍面板尺寸动画的唯一问题：`drawerFrame` 满宽按 `effectiveMaxColumns()`（含用户列数配置）计算，列数一变 `refreshAfterLayoutChange` 就立刻 `setFrame` 收窄窗口——内容还在 spring 就被裁。方案 E 注释本身写的是"宽度固定为**屏幕能容纳**的最大列数"，可见面板本来就在窗口内居中、`visibleDrawerFrame`/`ignoresMouseEvents` 穿透判定全按面板宽计算（与窗口宽解耦）——**把窗口满宽改为纯屏幕容量后，列数变化完全不改窗口 frame，面板动画无裁剪风险**。

## 改动

### 1. `LayoutEngineMutation.swift` — 抽出 `screenColumnCapacity()`

`effectiveMaxColumns()` 的容量分量独立成 `screenColumnCapacity()`（纯屏幕宽度公式），`effectiveMaxColumns() = min(model.maxColumns, screenColumnCapacity())`。行为不变，只是暴露容量分量。

### 2. `NotchPanelController.swift`

- `drawerFrame(for:)` 满宽改用 `layoutEngine.screenColumnCapacity()`（对齐方案 E 注释本意）；更新注释说明列数配置变化不再动窗口 frame。
- `refreshAfterLayoutChange(animated: Bool = false)`：`rebuildContent(animated: animated)`；`setFrame(drawerFrame)` 保留（网格指标变化仍会改窗口宽，但列数变化时 frame 不再变，成为无害 no-op）。

### 3. `NotchPanelContent.swift` — `positionSettingsWindow(animated:)`

设置面板贴挂抽屉底缘：抽屉高度 spring（重排堆叠/最小行数变化会增高）时面板需同步跟随，否则抽屉底缘先动、面板后跳出现短暂脱节。animated 时用 `NSAnimationContext`（duration 0.3 对齐 spring response，easeInOut）动画 `setFrameOrigin`；`rebuildContent` 内改为 `positionSettingsWindow(animated: animated)`。

### 4. `SettingsPages.swift` — 三个回调传 `animated: true`

`onMinChange` / `onMaxChange`（双游标滑条）与 `minRowsBinding`（最小行数 Picker）的 `refreshAfterLayoutChange()` → `refreshAfterLayoutChange(animated: true)`。

### 5. 不动画的路径（有意保持）

网格指标滑条（单元宽/高/间距/边距）走 100ms 防抖通知路径，保持现状不动画——拖动中连续 spring 会发黏；窗口 frame 本身永不参与动画（架构铁律，本次改动正是为了让列数变化不必动它）。

### 6. 测试（`LayoutEngineTests`）

新增 `testScreenColumnCapacityIsIndependentOfUserMaxColumns`：默认屏 `screenColumnCapacity()==8` 且不受 `setUserMaxColumns(2)` 影响；`updateScreenConstraint(width: 700)` 后 `==4`，`effectiveMaxColumns()==min(userMax, 4)`。动画与窗口行为本身无单测惯例，靠真机目检。

### 7. AGENTS.md

「抽屉动画是单一尺寸真源」条目追加：布局配置变化走 `refreshAfterLayoutChange(animated: true)` 的同批 spring 机制；`drawerFrame` 满宽取 `screenColumnCapacity()`，列数配置变化不改窗口 frame（杜绝"窗口先窄裁掉 spring 中的内容"）。

## 验证

`swift build` → `swift test` → `./Scripts/build.sh dev`；真机目检（先退旧实例再 `run`）：拖列数滑条时面板宽度 spring 平滑收缩、越界块滑入新位、无裁剪闪断；最小行数变化时高度 spring、设置面板跟随；恢复默认与网格指标滑条行为不变。
