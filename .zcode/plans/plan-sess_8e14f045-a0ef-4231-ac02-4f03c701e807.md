## 目标

最大列数调小后，已放置块若落在新有效容量（`effectiveMaxColumns()`）之外——即该页合并跨度超过容量、右侧块渲染时被面板裁掉——自动触发重新排布，把越界块修回可见窗口；且**修复先于落盘**，越界状态不再写进 layout.json。

遮挡的精确定义（探索确认）：渲染可见列窗口 = `[gridLeft, gridLeft + min(span, capacity))`，`setUserMaxColumns` 当前对块零处理、直接 `saveToDisk()`。

## 方案

### 1. `LayoutEngineArrangement.swift` — 新增纯函数 `repairCapacityOverflow(_ pageBlocks:capacity:)`

按页修复（复刻 `sanitized` 的骨架，但触发条件与修复手段不同）：

- **触发**：该页 `occupiedColumnRange` 跨度 > capacity，否则原样返回（`changed: false`）。
- **窗口**：`[rangeMin, rangeMin + capacity)`——**锚定该页左缘（gridLeft）不动**，只向右收缩。负列左扩布局天然成立（窗口起点就是最左块），且越界永远只发生在右缘。备选的"归一到 0 基窗口"会连左侧块一起搬，扰动更大，不取。
- **夹回**：越出右缘的块 `originColumn` 就近 clamp 进窗口（最近合法位置 = 贴窗口右缘）；**块宽超过容量**的极端情况无法用列位移修复，clamp 到窗口左缘、接受部分裁切（与窄屏现状一致，不改写块跨度、不违反 supportedSpans）。
- **安放**：窗口内原块按阅读序（`inReadingOrder`）**先固定（零移动）**，夹回块按阅读序殿后走 `placeInOrder`——撞上已固定块即向下移，行顶边锚定、列不再动（复用推挤核心，不触碰其语义）。不能用 `applyOrigins`/`validColumnRange`：越界状态下区间退化（lower > upper），clamp 会失效。
- **收尾**：`compactEmptyRows` → `compactEmptyColumns`（与 `commitArrangement` 同序同函数，只消整行/整列空洞）。
- **幂等**：修完跨度 ≤ 容量，重复调用零操作（滑条连续拖动每档触发一次，安全）。

### 2. `LayoutEngineMutation.swift` — 挂点

- `setUserMaxColumns`：`model.maxColumns` 更新后、`saveToDisk()` 之前调 `repairBlocksBeyondCapacity()`。
- 新实例入口 `repairBlocksBeyondCapacity()`：`Self.perPage` 按页分组套用纯函数，`result.changed` 才写回 `model.drawerBlocks`（无越界时零 model 发布、零数组改写；数组顺序按 perPage 契约保持）。
- **`updateScreenConstraint` 有意不挂**：换屏导致的容量变化是临时状态，修复会把布局永久改写（移回宽屏不可恢复），窄屏裁切维持现状。此为范围决策，如需覆盖可后续单独做。

### 3. `SettingsPages.swift` — 清理

删掉上轮滑条改造遗留的死代码 `columnBinding`（已无使用点）。

### 4. 测试 — `LayoutEngineTests` 新增「容量缩小修复」一节（`placeRaw` 增加 `page: Int = 0` 参数）

1. 越界块就近折回窗口右缘（0...1 + 6...7 → 4 列：b 落 2...3），窗口内块零移动，`validate()` 为空、跨度 ≤ 容量。
2. 窗口内目标列被占时撞上即下移（c 夹回 2...3 撞 b → row 1），a、b 原位。
3. 负列布局左缘锚定（-2...-1 + 4...5 → 4 列：b 落 0...1，跨度 -2...2 = 4）。
4. 修复腾出的整行空洞被压实（row 3 的块折回后上移到 row 1）。
5. 多页隔离：合规页逐字节不动、越界页修复、`drawerBlocks` 数组顺序（placementID 序）不变。
6. 幂等：8→4 与 8→4→8→4 两次结果逐块相同。
7. 块宽 > 容量的退化情形：不崩溃、其余块照常收拢、超宽块保持窗口左缘（validate 报 outOfBounds 属预期）。
8. 随机不变量（固定种子 ~30 轮随机缩放 4...8）：每轮后无重叠、跨度 ≤ 容量、行非负、数组顺序稳定。

### 5. AGENTS.md

「列双向扩大、行仅向下」条目追加越界重排契约（挂点、窗口锚定、幂等、超宽块不修、`updateScreenConstraint` 不挂的决策）；结构树 `LayoutEngineArrangement.swift` 描述补 `repairCapacityOverflow`。

## 不改的部分

推挤核心 `placeInOrder`/`pushDownOrigins` 语义、`sanitized` 加载净化、视图/控制器链路（设置页现有 `refreshAfterLayoutChange` 会自动把修复结果画出，无需新接线）、最小列数路径（下限只扩面板不留白裁块，无遮挡问题）。
