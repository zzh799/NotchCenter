# 删除 scrollUsage 声明体系，滑动让路统一走探针（最低支持提至 macOS 15）

## 背景与根因
亮度块声明 `scrollUsage: .always` 使宿主两条切页通路（`NotchPanelContent.swift:670` 触控板、`:734` 鼠标拖拽）无条件让路，整块成为切页死区。而滑杆实际只经命中测试消费鼠标拖拽（SwiftUI Slider/NSSlider 均不消费滚轮横向增量），块内 ScrollView 仅纵向。既然最低支持提到 macOS 15 后探针反向推断永远可信，声明体系整体失去存在必要——删除。

## 已知取舍（随用户决策接受）
第三方块若以非 ScrollView 机制（自定义横向手势）消费横向输入，探针看不见，其上会"切页+手势"双响应；未来如需可再补更细粒度机制。

## 验证
- `swift build && swift test` 全绿
- 真机（`./scripts/build.sh dev`，先杀旧实例）五场景：
  a) 触控板在亮度块任意位置（含滑杆正上）横向轻扫 → 跟手切页、亮度不变
  b) 鼠标拖滑杆 → 调亮度、不切页
  c) 鼠标在块空白区横向拖动 → 切页
  d) Scratchpad 满架时其上滑动让路、空/未满放行切页（探针新语义回归）
  e) Notes 等静态块上轻扫切页不受影响
  - 诊断：`NOTCHCENTER_SCROLL_PROBE_LOG=1`
