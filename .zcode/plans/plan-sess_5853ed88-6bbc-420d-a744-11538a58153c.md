### 根因

右滑落位的第二拍 `landDrawerSwipe` 把会话 `offset` 归零、网格层换目标页真实例，但**预览层不撤**，停在 `x = +原点页宽`，等下一拍异步 `rebuildContent(animated: true)` 清会话（`drawerSwipe = nil`）时才撤。该清理在 spring 动画事务里，预览层作为结构性移除走默认 `.opacity` 过渡 → 淡出 ~0.3s。当**目标页比原页宽**时，容器裁剪框已是目标页宽，预览层的 `[原页宽, 目标页宽]` 条带探回可视区 = 用户看到的"右侧另一份相同页面内容淡入再淡出"。左滑落位后预览层在 `[-目标页宽, 0]` 完全屏外，所以只有右滑闪。代码注释"此时它已在屏外，撤层不可见"的假设在宽目标页时不成立。

### 修复（预览层在落位帧就地撤除）

落位帧网格层与预览层像素重合（既有设计），此刻撤层不可见；异步清理随后不再有可见层可淡出。

1. **`Sources/NotchCenter/PanelUIState.swift`** — `DrawerSwipe` 在 `isLanding` 旁新增：
   - `var isLanded = false`（带注释说明宽目标页重影的成因与门控契约）；
   - `mutating func markLanded()`：`offset = 0; isLanded = true`（落位不变量收拢在一处，可单测）。

2. **`Sources/NotchCenter/NotchPanelContent.swift`** — `landDrawerSwipe`：`landed.offset = 0` 改为 `landed.markLanded()`；更正函数 doc 与 async 闭包里"此时它已在屏外"的失实注释（改为"预览层已在落位帧就地撤除，animated 清理无可见层"）。

3. **`Sources/NotchCenter/DrawerPanelView.swift`** — `pageSlide` 预览层条件改 `if let swipe = ui.drawerSwipe, !swipe.isLanded`，并补注释说明宽目标页下探回裁剪框的重影条带。

其余不动：会话仍由异步 `rebuildContent(animated: true)` 收尾清掉（保持 `swipeActive` 门控时序，换页元素交换的两条 spring 在落位帧仍关闭，不会引入交叉淡入回归）；胶囊高光只消费 `progress`，落位后 activePage 已切换，不受影响。

### 测试与回归钉

4. **`DrawerPageSwipeTests`** 新增：
   - `markLanded()` 语义：落位副本 `offset == 0`、`isLanded == true`、`isLanding == true`（收起守卫/新手势拦截不破）；新会话 `isLanded == false`。
   - 几何文档测试：右滑落位后预览层横坐标 = `gap`，目标页更宽时 `[gap, gap+目标页宽]` 与裁剪框 `[0, 目标页宽]` 相交（钉住"为什么必须按 isLanded 撤层、不能靠屏外假设"）。
