# ClipboardListProbe

剪贴板列表「惰性化 + 置顶/解顶跨分区移动」的**独立验证窗口**。

## 为什么单独做

生产插件里这件事迭代太慢：改一行要 `build.sh` + `assemble_app` 拷 dylib，量测要跑抽屉基准、要独占机器；而「LazyVStack 会让同 id 视图不重刷」这条结论当年没有留下可复现记录。

本探针把两件事抽出来，放进**同一份数据源**做 A/B：

| 面板 | 结构 | 行装饰 |
|---|---|---|
| 左 | 节嵌套；可在「非惰性 `VStack` / 嵌套 `LazyVStack`」间切换 | 复刻生产重型行（4 个 `@State` + 逐行 `GeometryReader` + 按压定时器 + `contextMenu`） |
| 右 | 扁平单 `ForEach` + `LazyVStack`（节标题也是 item） | 无状态行（零本地状态、零逐行几何、零 `contextMenu`） |

## 运行

```bash
./run.sh                    # 编译并开窗口
PROBE_SELFTEST=1 ./run.sh   # 无窗口自检（数据层 + 断言器有效性），失败退出码 1
```

单文件独立编译，只依赖系统 SDK，**不参与** NotchCenter 的 Tuist 构建，也不需要 `assemble_app`。产物在 `.build/`（已 gitignore）。

## 面板怎么读

每侧四个指标：

- **已物化行**：当前真正进了视图树的行数。这是本探针的头号证据。
- **峰值物化 / 总行数**：对比用。
- **首行挂载**：从触发重建到第一行上报的耗时，**只用于同窗口内横向对比**，不是上屏帧。
- **一致性判定**：`✓ 一致` / `✗ N 处冲突`。

一致性断言的做法：每一行在挂载、值变化、卸载时把自己**实际渲染用的值**（`RowStamp`：行 id、置顶态、正文、所属分区）上报给台账；台账按固定时点（0.3s / 0.9s 两拍）与模型逐字段比对。任何不一致——包括模型里已删除却仍在上报的**幽灵行**——都会计入冲突并显示在顶栏。

这把「按钮停在旧态」从目测传闻变成了可自动跑到红的断言。

## 手工核对清单

1. **结构对照**：左面板切到「节嵌套 · 惰性 LazyVStack」，看两侧「已物化行」。左应始终等于总行数（惰性只作用于「节」），右应只有视口内的十来行。
2. **视口内置顶**：点某行行尾的图钉，该行应立刻跳到置顶区，徽标由「普通」变「置顶」，两侧同步。
3. **视口外置顶**：按「置顶最后一条」，把视口外的行搬进置顶区，再滚到顶部确认它在、且徽标正确。
4. **解顶回落**：按「解顶首条置顶」，该行应落回最近区首位。
5. **置顶溢出**：连点 6 次「置顶最后一条」，第 6 次应触发最早置顶项自动解顶并落回最近区。
6. **跨分区后立即操作**：置顶一行后立刻再点它的图钉解顶，确认按钮态跟着走（旧态残留最常在这里露头）。
7. **压测**：按「压测 100 次（自动断言）」。每步先把目标行滚进视口（惰性面板否则验不到），再置顶/解顶，然后两拍校验。窗口内日志会逐步汇报，零冲突即通过。
8. **只隔离结构一个变量**：勾上「右侧也用重型行」，两侧行成本一致，此时两侧的差异只来自列表结构与惰性。

## 已知边界

- **离屏行验不到**：惰性面板只对已物化行做断言，所以压测里必须先滚动再操作；这也是压测脚本主动滚动的原因。
- **首行挂载是近似值**：不是上屏帧时间。真实展开耗时仍以宿主基准（`NOTCHCENTER_DRAWER_BENCH`）为准。
- **不碰真实剪贴板**：点击行的「写回」是空操作，探针只用内存里的假数据。
- **行高固定**：目标写法的锚点靠「整表一个 `GeometryReader` + 固定行高推算」，所以两侧行高都钉死；生产落地时这也是配套条件（单行 `lineLimit(1)` 本就固定内容高）。
- 断言器自身的有效性由自检覆盖：自检里会人为制造一次过期上报和一次幽灵行，断言器必须抓到；再修正后必须转干净。否则「0 冲突」可能只是断言器坏掉。
