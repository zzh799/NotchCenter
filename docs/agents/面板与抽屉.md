# 面板与抽屉 — 领域约定

> [AGENTS.md](../../AGENTS.md) 的领域子文档：面板刷新、抽屉动画、窗口生命周期的完整机制与历史教训。动到 `Sources/NotchCenter/` 面板相关代码前先通读本文。分页与滑动切页另见 [`抽屉分页与滑动切页.md`](抽屉分页与滑动切页.md)。

## 面板内容刷新走 PanelUIState

透明无边框 `NSPanel` 上重新赋值 `NSHostingView.rootView` 不能保证立即重绘；宿主视图只在创建时设置一次 root，之后一律通过 `PanelUIState` 的 `@Published` 属性驱动 SwiftUI 刷新。新增面板状态时加到 `PanelUIState`，不要绕过它直接操作视图。

## rebuildContent 的块视图复用键缓存

`rebuildContent` 是编辑提交/切页/展开的高频路径，历史上每次都为**每个块**（紧凑 + 抽屉）重新 `block.makeView`——AnyView 新实例会让 SwiftUI 把没变的插件视图整树重渲染。现在 `buildCompactElements`/`buildDrawerElements` 走 `BlockViewCacheKey` 复用：键是 **makeView 可观察输入的完整快照**（pluginID/blockID/placementID、entry 身份 `ObjectIdentifier(entry)`、layoutInfo 全字段——region/frame/origin/跨度/isEditing/compactSlotIndex/isPreview、hasSettings），逐项相等 ⟺ 重新 makeView 必然产出等价视图值，此时直接复用上一次的视图值。

三条失效契约（缺一会出现"视图读到旧状态"类幽灵 bug）：
1. **`BlockLayoutInfo` 新增字段（或插件开始读某个此前没读的输入）必须同步扩键**——漏掉就是复用判据不完整。
2. **插件启用/禁用/安装/卸载必须整体失效两份缓存**：makeView 依赖插件全局状态（如 NotesModel 按 store 重新解析、`pluginWasDisabled` 清实例数据），entry 对象身份在禁用/启用间不变、键察觉不到——`onEnabledPluginIDsChanged` 回调里已统一 `removeAll()`（安装/卸载都经该回调）。
3. **预览副本（`isPreview: true`）不回写缓存**：副本缺插件的激活副作用，不能顶替真实例身份，回写会把真实例的复用键挤掉；提交布局构建与旧缓存做**并集**（切页往返时另一页的键保留），并按现存 placementID 修剪（UUID 全局唯一，无误配风险）。滑动切页自 2026-09-06 起直接以 `isPreview: false` 构建目标页真实例并回写、落位沿用会话元素不重建（见 [`抽屉分页与滑动切页.md`](抽屉分页与滑动切页.md)），本条仅约束未来再引入预览副本的路径。

另：钉住按钮只翻 `uiState.isPinned`（@Published，顶栏图标与收起守卫都直接读它），**不要**在 `onTogglePin` 里加回 `rebuildContent()`——那是纯浪费的全量重建。

## 展开成本结构：内容"每次展开全额重付"，温存把它省掉

`DrawerPanelView` 的 `content` 分支原本由 `if ui.isDrawerExpanded` 门控——收起即整树卸载、展开即整树重建。现在门控是 `ui.isDrawerExpanded || warmth.keepsContentMounted`：**收起后内容温存 300s**（`DrawerContentWarmth`），窗口内再展开即省掉整棵内容树的首次渲染。代价与语义边界见[决策记录](../agent-notes/implemented/2026-09-11-drawer-content-warmth.md)，本节只留可操作结论。

分段的量级（Release、每页 12 块、逐页 ×3 轮）：

| 段 | 实测 | 说明 |
|---|---|---|
| `rebuildContent`（引擎查询 + `makeView` 缓存命中） | 0.3–7ms | **不是瓶颈**，与块数基本无关 |
| 窗口上线（`presentDrawer` 同步段） | 2–66ms；温存下会承载内容首渲染 | 满高透明窗口 orderFront + setFrame |
| SwiftUI 挂载 + 首次布局 | 亮度滑杆/番茄钟/镜子 **8–13ms/块**；笔记 **60–160ms/块** | 主战场，随**内容**而非块数；温存命中时 ≈ 0 |
| 内容淡入尾段（固定） | ~340ms | `DrawerPanelView.onChange` 里 0.2s 延迟 + 0.18s 淡入，温存也消不掉 |

**同页重开（温存命中）是本轮主要收益**：N=20 的页从 `visible` 2070ms 降到 552ms（−73%），降幅随块数单调增长（N=2 只有 −22%，因为剩下的正是那条固定尾巴），`layout` 段稳定降 −75~−85%。**温存不帮忙的两种情形**：换页（内容 identity 全变，必然全额重付）与温存过期。注意基准 `uniform` 模式**每步都换页**，是构造出来的最坏情形：真实使用里换页要求抽屉张开，`drawerActivePage` 的写入点全部只在展开态可达，收起态换页不存在。

**剪贴板块是唯一量级异常的块，且成本只跟行数走**：≈ **行数 × ~6ms/块/行**（单块 50 行 ≈ 317ms、20 行 ≈ 160ms）。把历史里 4 万字的正文（其中 5 条 4–12k 字的 HTML）换成两个汉字只省 **6%**，摘掉可见性探针省 **0%**，而把行数从 50 压到 10 省 **75%**。消耗在逐行视图本身：每行一个 `blockPopoverTrigger` 手势 + `contextMenu` + a11y 标签 + 背景描边。`ClipboardHistoryBlockView.historyList` 曾用**非惰性** `VStack`，理由是"`LazyVStack` 会让置顶/解顶跨分区移动时同 id 视图不重刷，见其内注释"——该结论已在 2026-09-12 定位为**结构误用**：旧写法「`LazyVStack` → `ForEach`(节) → 节容器 → `ForEach`(行)」里惰性容器的直接子项只有两个"节"、行藏在节容器内部，既从未拿到行级惰性，又自己造出了"同 id 在两个 `ForEach` 容器之间搬家"。现已改为**扁平单 `ForEach` + `LazyVStack`**（行身份 = `entry.<uuid>`，不含分区，跨分区移动不换身份），抽屉块与库页两侧列表同批惰性化，见[决策记录](../agent-notes/implemented/2026-09-12-clipboard-lazy-list.md)。**静态收益**是物化行数由"总行数"降到"视口内行数"（300×240 的块约 6–8 行，50 行块 ≈ 317ms → 约 40–50ms），**真机复量未做**；剩余可选增量是削单行装饰（`contextMenu` / a11y）与逐行几何采集改造，边际收益已被惰性化吃掉大半。

诊断入口：`NOTCHCENTER_DRAWER_PERF=1`（每次展开打印一行分解）、`NOTCHCENTER_DRAWER_BENCH=1`（用户真实布局逐页 ×N 轮）、`=synthetic` / `=uniform` / `=reopen`（自造布局：N 曲线 / 同型块对照 / 同页连续重开，块型取本机已加载可用的块，读写重定向到临时文件，不碰真实布局）。轮数经 `NOTCHCENTER_DRAWER_BENCH_ROUNDS` 控（默认 3），跑完打印汇总表自动退出。分量归因另有三把同族开关：`NOTCHCENTER_DRAWER_WARM_SECONDS`（温存窗口，`0` = 收起即卸载，同一二进制内做开/关 A/B）、`NOTCHCENTER_CLIPBOARD_ROW_CAP`（压行数）、`NOTCHCENTER_CLIPBOARD_DIAG=text-off|content-off|probe-off`（分别摘正文体积 / 列表内容 / 可见性探针；设了开关会在启动时打一行 `[clipboard-diag]` 自证生效）。实现见 `Sources/NotchCenter/DrawerOpenPerf.swift`；**改完展开路径必须用同一模式复量**，否则数字不可比。

**worktree 构建注意**：`git worktree` 里 `.git` 是文件，Tuist 认不出根目录——需要在 worktree 根放一个 `Tuist/` 标记目录（本地 `.git/info/exclude` 已排除，不入库），并让 `.build/xcode/SourcePackages` 与 Xcode DerivedData 复用主仓已解析的 SPM 缓存（无网环境否则解析必失败）。

**改完插件后，先确认 `.app` 里的插件 bundle 真的换了**：`xcodebuild` 只产出 `Build/Products/<cfg>/lib<Name>.dylib`，把 dylib 拷进 `NotchCenter.app/Contents/PlugIns/<Name>.bundle` 的是 `build.sh` 的 `assemble_app`，而它开头一句 `rm -rf "$plugins_out"`（递归上百个文件）在受限/沙箱环境里可能被批量删除闸门拦下——此时 `set -e` 让脚本中止，**但 xcodebuild 已经打过 `BUILD SUCCEEDED`**，于是留下"宿主新、插件旧"的产物。这类假象会让整轮性能复量白跑（症状：新加的诊断开关明明设了却毫无效果）。改完插件后至少核一次 bundle 二进制的时间戳或用一个只应在新代码里出现的字符串 `grep` 一下：`grep -c <新串> .build/xcode/Build/Products/<cfg>/NotchCenter.app/Contents/PlugIns/<Name>.bundle/Contents/MacOS/<Name>`；就地覆盖 dylib + 重签可以绕开那句批量删除。

## 抽屉动画是单一尺寸真源（参考 codex-island 的 model.size 模式）

`PanelUIState.drawerWindowSize` 是可见面板尺寸的唯一 @Published 真源（收起 = 紧凑带尺寸），一切尺寸变化（展开/收起/编辑增高/增删块/缩放预览）必须在 `withAnimation` 里改变它；容器视图 frame 直接绑定它做 spring 变形。抽屉窗口固定满高、永不参与动画；穿透命中 = hitTest 限定可见矩形 + `window.ignoresMouseEvents` 光标跟踪双机制（缺一不可，仅 hitTest 窗口仍会抢焦点）。不要恢复 revealProgress 遮罩插值或任何“窗口跟随内容”的桥（NSAnimationContext/preference/解析 spring 均已试错，均有时钟偏差）。

**布局配置变化的平滑重排走 `refreshAfterLayoutChange(animated: true)`**（设置页列数双游标滑条与最小行数回调；网格指标防抖路径保持瞬时）：`rebuildContent(animated:)` 把 `drawerWindowSize`/`drawerElements`/`drawerGridLeftColumn` 同批写进 spring，块经网格既有的两条 `.animation(value: placement)` 平滑滑入新位（重排修复也走这条，无需额外动画代码）。

配套约束：**`drawerFrame` 的固定满宽取 `screenColumnCapacity()`（纯屏幕容量，不受用户列数配置约束）**——列数变化不改窗口 frame，`setFrame` 成为无害 no-op，否则“窗口先窄、spring 中的内容被裁”复现。

## 设置面板摆位：抽屉下方优先 + 屏幕底部兜底

设置面板（独立 titled NSPanel，popUpMenu 级）的垂直摆位由 `NotchGeometry.settingsPlacement` 裁定、**`positionSettingsWindow()` 落位**（**只改 Y 轴位置**：窗口已可见且仍在锚定屏上时保留用户拖动后的横向位置——切页/布局提交的重摆不得横向归位；首次定位或跨屏才回屏幕中线与抽屉同轴，避免"新屏的 Y + 旧屏的 X"错位）：

- **抽屉下方**：抽屉下方放得下（窗口完整落在抽屉可见底缘之下一个 `gapFromSettings`，且底缘仍高于 `visibleFrame.minY` + `bottomInset`）就贴抽屉底缘——面板与抽屉上下咬合，改设置时视线不离刘海；
- **屏幕底部**：放不下则退回 `visibleFrame` 底缘 + 间距（已避开 Dock），由抽屉限高让位。

裁定只用抽屉的**自然高度**（`naturalDrawerContentHeight`，未经限高）——限高读摆位、摆位若再读限高会自激（抽屉被裁矮 → 下方永远"够"）。摆位缓存在 `NotchPanelController.settingsPlacement`，由 `updateSettingsPlacement()` 写入；**只随离散节点重摆（`positionSettingsWindow(animated:)` 一次性 0.22s 平移），不要恢复"逐帧 spring 跟随抽屉底缘"的旧桥**。动画分支必须经 `animator().setFrame(_:display:)`——**`setFrameOrigin` 不在 NSWindow 可动画方法之列，经 animator 代理调用会被静默吞成 no-op**，表现为摆位缓存已重裁、窗口纹丝不动（"切页后设置窗口不让位"事故的根因，摆位探针 `NOTCHCENTER_PLACEMENT_PROBE=1` 可复现实锤）。触发重裁的节点：

- 打开设置：先于 `expand()` 裁定（限高要直接落进展开的 spring，不先弹满再回缩）；跨屏搬移后再补裁一次；
- 布局提交：`refreshAfterLayoutChange`（改列数、网格指标）与 `refreshAfterEdit`（编辑提交——增删块、抽屉内拖拽/缩放落定、组件页拖块落位）；两者同序：**先重裁摆位再重建**（限高读摆位），抽屉自然高度变了设置窗口就让位（贴抽屉下方 / 放不下退屏幕底部）；
- 切页/加页：`rebuildContentAfterPageChange`（抽屉高度随页变化；不做抽屉窗口 `setFrame`，省掉满高窗口重绘）。

**拖拽/缩放/落位预览不重摆摆位**：两条预览路径（`applyPreviewWindowSize` / `applyDropPreviewWindowSize`）把 `drawerMaxVisibleHeight(for:)`（含设置限高）传进 `DrawerLayoutMetricsResolver`，抽屉在预览中**不会长回自然大小**，设置窗口因此全程不动。不要恢复"预览按预览后高度让开面板"的旧桥（`syncSettingsPlacementForPreview` 已删）：预览绕过限高会把抽屉撑回自然大小盖住面板（"组件页拖动组件抽屉恢复正常大小"事故），且拖拽中设置窗口跟着跳。预览中被截掉的内容与落点走 ScrollView / 现有可见区，让位统一发生在松手提交后（`refreshAfterEdit` 的摆位重裁）。

重叠由**打开期间的抽屉限高**保证，两种摆位共用同一条不变量：`drawerWindowSize(for:)` 在 `isSettingsPresented` 时按 `NotchGeometry.settingsCappedDrawerHeight`（抽屉可见底缘 ≥ 设置窗口顶缘 + 间距）封顶——贴抽屉下方时该上限恰等于裁定时的自然高度（空操作，抽屉长高会触发重裁摆位而不是被悄悄截断）。限高只在能容纳最小抽屉时生效，放不开则整体放弃（允许重叠、不塌成 0）。**所有抽屉可见尺寸写入点（展开、重建、两条预览路径）必须统一经 `drawerMaxVisibleHeight(for:)` 封顶**，任何一条绕过都会复现"预览盖面板"。打开与关闭路径都必须触发一次尺寸重算（`refreshAfterLayoutChange(animated: true)`），限高的施加/解除才落进 spring。

## 动画容器必须顶缘钉死、收起不得无动画贴起点

`DrawerPanelView` 绑定 `drawerWindowSize` 的容器 frame 必须 `alignment: .top`——收起过渡中抽屉内容退出布局（快照仍挂在树里淡出），VStack 与仍在收缩的容器高度不一致，默认 `.center` 会把只剩紧凑带的 VStack 顶出容器，图标随之下坠（展开方向靠 ScrollView 伸缩掩盖了同一问题）。`setDrawerRevealed` 里“无动画贴起点”只属于展开分支（贴紧凑带再 spring 长出）；收起的起点就是当前尺寸，若也无动画写成目标，收起会瞬跳且 easeOut(0.16) 动画丢失。

## 抽屉窗口单例不变量：任一时刻至多一个屏的抽屉在屏

`collapse()` 的完成回调存在 0.43s 窗口（0.25s 延迟 + 0.18s 等收起动画），期间鼠标移到另一块屏触发跨屏展开会以“已重新展开”为由跳过旧屏的 `orderOut`，旧屏抽屉窗口永久残留——它与活动屏共享同一份 `uiState`，每次展开都渲染出一份一模一样的活抽屉（用户报告“新建笔记多出一块面板”的根因）。

因此 `expand()`（含已展开分支）必须清扫 `hideOtherDrawers(keeping:)`，收起完成回调只保留“当前展开屏”而不是整体跳过，`syncScreens()` 移除 stale pair（NSScreen 身份在显示重配后更换，同一物理屏也会命中）时必须显式 orderOut 其两个窗口。不要把完成回调改回“捕获 pair + isExpanded 短路”。

## 插件块内不得让隐藏窗口复活（共享状态 × 每屏一份视图树）

宿主把同一份 block view 塞进每块屏的抽屉树，插件里按 placementID 共享的交互状态（如 NotesPlugin 的 `EditorInteractionState`）会被**所有屏的实例并发 bind**，谁最后落地谁占有 `textView`/`containerView` 引用——隐藏屏实例赢得竞态后，任何 `makeKeyAndOrderFront`（焦点、激活）都会把已收起的抽屉窗口重新拉上屏，表现为“新建笔记时另一块屏多出一块一模一样的面板”。

约束：绑定入口必须拒绝“隐藏窗口候选覆盖可见现任”（可见候选永远放行）；任何聚焦/激活调用前必须 `window.isVisible` 防护。滑动切页的预览层也属同一族事故，插件侧配套义务见 [`抽屉分页与滑动切页.md`](抽屉分页与滑动切页.md) 的 isPreview 契约一节。

## 抽屉内的确认与提示一律用内联浮窗，禁用模态弹窗

`NSAlert.runModal()` / `confirmationDialog` 是**独立 key 窗口**：鼠标移过去的瞬间指针已离开抽屉，宿主判定「已移出停留区」而安排收起；同时模态循环阻塞主线程，收起动画与状态更新都推进不了，弹窗就悬在一个已经/即将收起的抽屉上方——点不到、也关不掉（删页确认曾因此卡死）。

约束：抽屉内触发的确认与提示一律走 Kit 的内联浮窗，两种形态按锚点选：

- **`BlockPopover` + `InlineConfirmPanel`**：独立 `nonactivatingPanel`（不抢焦点），贴锚点下方弹出。删页确认（分页胶囊 ✕，`NotchPanelContent.removeDrawerPage(_:anchorFrame:)`）与快速区重动作确认用它。
- **`InlineConfirmOverlay`**：半透明遮罩叠在原卡内，用于卡内确认。

例外：锚点在**设置窗口**内的提示（如组件目录的「抽屉页已满」）可以继续用 `NSAlert`——设置窗口打开期间抽屉常驻（`DrawerStayConditions.isSettingsPresented`），不存在「抽屉先收起」的问题。判断依据是**锚点所在窗口是否会随鼠标离开而收起**，不是弹窗类型本身。

## UI 风格

抽屉强制深色（`.environment(\.colorScheme, .dark)`），背景接近纯黑半透明，顶部圆角遮罩（`TopAttachedRoundedShape`）。改动视觉时保持“贴近刘海”的观感，遵循 [`docs/DESIGN.md`](../DESIGN.md)。抽屉块的卡片壳一律用 Kit 的 `BlockCard`（底色/发丝描边/可选悬停），长按浮窗触发一律用 `.blockPopoverTrigger`——不要在插件里自绘背景描边或手写 frame 追踪与长按手势。
