# 布局引擎与网格 — 领域约定

> [AGENTS.md](../../AGENTS.md) 的领域子文档：布局引擎、网格几何与编辑模式的完整机制与历史事故。动到 `LayoutEngine*` / `DrawerGridGeometry.swift` / `DrawerBlockContainer.swift` 等代码前先通读本文。

## 块尺寸：像素三档换算出的格跨盒

布局/引擎层内部仍用 `GridSpan`（格跨）表达块尺寸——**引擎不感知像素**。允许的格跨盒 `[min…max]` 由块的**物理像素三档**（`minSize/maxSize/recommendedSize`，见架构文档 §4.2）按当前格子尺寸换算而来（`NotchBlock.sizeBox(cellWidth:cellHeight:)`：min 向上取整、max 向下取整至少 1 格、recommended 就近取整夹进盒内；不含格间间距）。宿主在元素构建处换算一次（`DrawerElement.minSize/maxSize` 即当前格下的盒角），手势层/引擎只消费格跨盒，不做像素换算；无离散档位目录——盒内任意整数跨可达。存量超盒跨度照显不视为损坏，首次拖拽被钳进盒内。

## 缩放握把的量化必须带死区、平移量必须在稳定坐标系度量

`ResizeHysteresis.quantized` 只在连续位移越过当前格的半步边界 ± band 之外才换格；`DrawerBlockContainer.resizeGesture` 必须用 `coordinateSpace: .global`。不要改回朴素 `round()`、整数距离迟滞（无实际死区，边界抖动闪烁），也不要改回默认 `.local`——握把随预览增长平移一格时 local 平移量瞬间反跳一整格，死区吸收不了，形成逐像素自激振荡。回归见 `ResizeHysteresisTests`。

## 拖拽推挤算法不能改回“同步 +1 行”

`pushDownOrigins`（`previewArrangement` 的核心，缩放推挤复用同一实现）的逐块安放语义是历史 bug 的修复——旧实现让所有重叠块同步下移，相对位置不变、永不分离，靠次数上限退出并把残留重叠写盘，导致粘连块对与失控行号。改动推挤逻辑前先读 `DragReorderReproTests`；`LayoutEngine` 加载时会自动净化含重叠的损坏 layout.json，勿删除该路径。

安放核心 `placeInOrder` 的"首个不重叠行"查找是**禁放区间跳跃**：对每个列区间相交的已固定块取禁放行区间 `[F.minRow − h + 1, F.maxRow − 1]`，按起点排序后从 originRow 起跳过被覆盖行。它与旧的"逐行 +1 直到不重叠"**逐位等价**（首个不被任何区间覆盖的行），但旧实现每步重扫全部已固定块，是 O(n²·行高)——192 块实测 6.5ms/次（拖拽预览每帧都跑）；区间跳跃后 2.4ms，剩余成本是固有的逐块对扫描。基线数字见 `LayoutPerformanceTests`；改回逐行下移或改变落点语义都会被该套件的预算闸门拦下。

## 编辑模式契约：不留空行 + 缩放推挤 + 面板贴合

所有变更（移动/移除/缩放/提交）后 `compactEmptyRows` 会闭合整行空洞（下方整体上移；行内部分留白保留，加载净化的留白保护不受影响）；`resizeDrawerBlock` 扩大遇下方块不再回退而是推挤下移，预览与提交走同一算法（所见即所得）；窗口高度经 `previewBottomRow`/`refreshAfterEdit` 随内容行数按需增减。回归见 `LayoutEngineTests` 的“编辑模式契约”一节。

## 列双向扩大、行仅向下（originColumn 可为负）

行始终顶边锚定只向下扩大（originRow 不变、非负）；列支持左右双向——块被拖出左侧时格网向左扩大（originColumn 变负，`validColumnRange` 保证合并后跨度 ≤ 容量），单右下握把只向右下扩大（无左右双握把）。渲染横坐标 = `(originColumn − gridLeft) × 步长`、宽高按占列跨度（`occupiedColumnRange`），面板绕刘海居中所以列扩大视觉上左右对称。预览期 `applyPreviewWindowSize` 必须把 `drawerWindowSize`/`drawerContentSize`/`drawerGridLeftColumn` 放进**同一次 withAnimation（与块推挤同帧，不等松手）**；`compactEmptyColumns` 会闭合负列空洞（左侧块向 0 右移，与右移对称）。

**最大列数缩小触发越界重排**：`setUserMaxColumns` 在落盘前按页跑 `repairCapacityOverflow`（实例入口 `repairBlocksBeyondCapacity`，经 `perPage` 分组）——渲染可见列窗口 = `[gridLeft, gridLeft + capacity)`，合并跨度超容量即右缘块被裁；修复**锚定该页左缘（gridLeft）不动**，越出右缘的块把 originColumn 就近夹回窗口（贴右缘），再按「窗口内原块（阅读序）先固定、夹回块殿后」走 `placeInOrder`（撞上即下移），收尾按页压实空行/空列；幂等（滑条连续拖动每档触发一次）；**不能用 `applyOrigins`/`validColumnRange` 修**（越界状态下合法区间退化 lower > upper，clamp 失效）；块宽超过容量的极端情况不修跨度、夹回窗口左缘接受部分裁切（与窄屏现状一致）；`updateScreenConstraint` 有意**不挂**修复——换屏容量变化是临时状态，修复会永久改写布局。

回归见 `LayoutEngineTests` 的“编辑模式契约：列双向扩大（左扩）”与“容量缩小修复”两节及 `DragReorderReproTests` 的列跨度不变量。

## 行列容量是「屏幕 ÷ 格」的纯推导；档位动态，存量不回改

容量（能摆下几行几列）由 `GridCapacity`（纯函数，不建引擎、不读指标单例即可测）从**屏幕可用尺寸 + 当前 `GridMetrics`** 推导：列容量 = `width(n) + 内边距×2 ≤ 可用宽` 的最大 n（与旧 `screenColumnCapacity` 逐位等价——抽屉窗口固定满宽按它取，勿改口径）；行容量额外扣顶栏与底边距（高度预算 = `topBar + height(rows) + padding`，与 `drawerWindowSize` 同源）。

屏幕可用高经 `LayoutEngine.updateScreenConstraint(width:height:)` 由控制器写入，高度取 `maxDrawerHeight`（屏高 − 顶部留白 − 紧凑带）；**不要**喂含设置面板让位的 `drawerMaxVisibleHeight`——那值随面板开合瞬变，会让档位在打开设置时突然缩水。`availableScreenHeight == nil` = 高度未约束（测试与未接屏路径的默认，行侧不夹），所以单参 `updateScreenConstraint(width:)` 有意不清空它。

**多屏取所有屏的最小可用尺寸**（`updateScreenConstraint(availableScreenSizes:)`，控制器从全部 pair 聚合喂入）：宽、高**各自**取分量最小（`GridCapacity.minimumAvailability`）。布局是全屏共享的一份（架构文档 §7.1 / §7.2「按最小分辨率屏幕算」），按单块屏算的后果是抽屉搬到小屏放不下、行列档位随活动屏跳变——所以该路径**不接收 pair**，没有"当前屏"这回事，`expand()` 换屏时调用它只是保新鲜、结果不变。空序列不写任何值（无参考屏，兜底在控制器：`1440`/未约束高）；值未变则不写（`@Published`，展开时会高频调用，免得设置页无谓重算档位）。

`LayoutModel.maxColumnsRange / minRowsRange / minColumnsRange` 已降级为**持久化解码与绝对兜底边界**（上界统一为 `absoluteGridLimit = 64`，非约束性——架构文档 §7.2 的「上限 = 屏幕容量」由档位落实），不再是档位真源；档位由 `selectableMaxColumnsRange`（`min(2, 列容量)...列容量`）、`selectableMinColumnsRange(maxColumns:)`（`min(3, 上限)...上限`，保住"不塌成一列窄条"的设计意图）与 `selectableMinRowsRange`（`1...行容量`）按屏幕与格尺寸现算，三者恒非空——容量不足时退化为单点，绝不构造空 `ClosedRange`。设置页滑条/下拉消费它们，`ColumnRangeSlider.valueRange` 与 `ColumnRangeSliderMath(valueRange:)` 因此**必传**、不给静态默认（漏传就会悄悄退回写死范围）。

## 最小行数 / 最小列数只夹尺寸、不动块原点

`layout.json` 的 `minRows`（默认 1）与 `minColumns`（默认 3）是网格行列下限，块不够时面板补空白格到该尺寸；**默认值同时是旧文件缺键的回落值**，所以升级后抽屉至少 3 列宽（自定义 `init(from:)` 不跑成员式 init 的夹紧——新字段必须在解码处各自夹，且 `CodingKeys` 漏加会被合成编码器静默丢弃）。

生效下限的唯一出口是 `LayoutEngine.minimumRowCount()` / `minimumColumnCount()`，**两者都再夹一次容量**（行夹行容量、列夹有效容量）：最大列数只有 2 或窄屏时最小列数退化为"面板恒为满宽"，但绝不宽出 `drawerFrame` 的定宽窗口而被裁；小屏上 9 行下限夹到行容量，抽屉不再凭空多出视口外看不到的空白行。换屏（容量变化）是**临时状态**：只改生效值与档位，不改块原点、不挂越界修复、也不回改存量配置（`setUserMinColumns` 在最大列数小于设计下界时忽略写入，把最大列数调回去时原设置仍然生效；三个 setter 的**存储**夹紧仍走静态兜底范围）。

两条同源铁律：网格容器高度（`DrawerGridGeometry.bottomRow`/`contentHeight`）与窗口高度（`DrawerLayoutMetricsResolver`）必须按**同一份** `minimumRows` 夹紧，且 `uiState.drawerGridMinRows`/`drawerGridMinColumns` 必须与 `drawerContentSize` 在**同一次** `rebuildContent` 里写——漏任何一处就是落在留白格里的块与占位框被 ScrollView 裁掉。`compactEmptyRows`/`compactEmptyColumns`、推挤、落点夹紧与校验一律看不到这个下限。

回归见 `LayoutEngineTests` 的"配置项：最小行数 / 最小列数"与"行列容量与动态档位"两节、`GridCapacityTests` 与 `MinimumGridSizePersistenceTests`。

## 失效摆放：判据单一，清理分三档

"摆放是否还指向真实存在的组件"只有一个判据：`LayoutEngine.isLivePlacement` → 注入的 `placementLiveness`（宿主侧 `NotchPanelController.placementAvailability`，三态 `.live` / `.pluginDisabled` / `.missing`）。**插件只是被停用不算失效**（停用可逆），所以 `invalidPlacementCount()` / `purgeInvalidPlacements()`、调试页的"删除无效组件"计数、以及插件列表的「使用中」徽章（`inUsePluginIDs`）看到的必须是同一套判断。任何新增的"哪些摆放是坏的"逻辑都要过这里，不要另养第二套。见 [Agent Note 2026-09-25](../agent-notes/implemented/2026-09-25-plugin-in-use-placement-criterion.md) 与 [2026-09-11](../agent-notes/implemented/2026-09-11-invalid-component-visibility.md)。

清理分三档，口径都是上面的 `.missing`：

1. **release 构建启动时自动**——`LaunchMaintenance.run`，由 `NotchPanelController.init()` 在 `restoreEnabledState` 之后、`refreshCompactGeometry` 之前调用（早于前者会把尚未注册的快捷动作槽误判失效，晚于后者得自己补一次刷新）；
2. **debug 构建不自动清**——留给「设置 → 调试 → 删除无效组件」，开发期要靠残骸复现问题；
3. **用户停用插件**时，二次确认后连带移除该插件**全部**摆放（`removePlacements(forPluginID:)`）。这一档走的是 pluginID 而非 `placementLiveness`，所以比前两档更宽（连失效残骸一起清）。

**紧凑槽位的删除必须走 `CompactSlotOrder`，不能 `filter` 数组**：数组下标决定左右分列（`screenOrder` 只依赖总数），长度一变映射就变，直接过滤会让被删项之后的图标**整体换列**（屏幕上"删一个、其余跳边"）。单次删用 `removing(_:at:)`，批量删用 `removingAll(_:where:)`。

回归见 `LayoutEngineTests` 的「使用中判据与按插件移除摆放」一节与 `LaunchMaintenanceTests`。
