# 紧凑区与活动摘要 — 领域约定

> [AGENTS.md](../../AGENTS.md) 的领域子文档：刘海两侧紧凑区带宽与活动摘要芯片的完整机制。动到 `CompactPanelView.swift` / `CompactSummary.swift` / `NotchGeometry.swift` 前先通读本文。

## 紧凑区宽度动态、不固定槽位（架构文档 §5.2）

`compactSlots` 数组长度即当前紧凑图标数（元素无 `null` 占位；移除即删元素闭合空隙，旧版固定 3 槽文件加载时经 `normalizedCompactSlots` 剥除空槽）。带宽 = `CompactStripLayout(slotCount:)`：图标按添加顺序**左右均衡交替**排布（偶数索引在左、奇数在右，均从靠刘海一侧排起），两面板等宽（按较大一侧实际槽数）保证黑色带绕刘海左右对称、刘海中心恒为带宽中心。

视图侧必须从 `PanelUIState.compactCount` 取数量（`layout.compactStrip(slotCount: ui.compactCount)`），不得硬编码槽位数——宿主视图只在创建时设置一次 root，`layout` 是被捕获的旧值。

**几何状态同步集中在 `refreshCompactGeometry()`**：把引擎计数推到各 pair 镜像（`pair.compactCount`/`pair.compactStrip`）与 `uiState.compactCount`，并按新带宽重摆热区窗口；任何增删紧凑图标（`onAddBlock`/`onRemoveBlock`）与换屏（`syncScreens` 后）的路径必须先调它、再调 `rebuildContent`（后者保持纯内容重建、无窗口副作用）。引擎计数只能经 `compactIconCount` / `compactStrip(for:)` 访问，不要在各消费点直接读 `layoutEngine.compactSlots.count`。增删紧凑块没有“槽满”概念（紧凑块从设置组件页拖入，不设数量上限）。

## 活动摘要：紧凑带内芯片、不新建窗口（架构文档 §4.10）

插件进入活动状态（计时中、正在播放等）时经 `HostController.showActivitySummary` / `removeActivitySummary(id:)` 提交/收回 `ActivitySummary`，宿主在刘海紧凑带内渲染一行「图标 + 文案 + 迷你进度」芯片——**不新建窗口、不遮挡屏幕内容区**（旧活动岛窗口机制已整体移除，决策见 Agent Note `2026-09-03-compact-area-activity-summary`）。

- **提交与收回**：`showActivitySummary` 同 id 原位覆盖（不改变摘要序列的新旧次序，最新条目恒在序列尾），新 id 追加到序列尾；宿主做等值短路（内容未变不触发）。`removeActivitySummary(id:)` 把 id 出列，id 不存在时无副作用。进度按整秒节流等节流逻辑在插件侧（如 1s ticker），宿主不做频率假设。
- **展示排布**（`PanelUIState.visibleSummaryPair` → `ActivitySummaryDisplay.visiblePair(from:drawerExpanded:)`，纯函数可测）：至多展示最近两条——**最新在左、次新在右**，仅一条时在左；抽屉展开期间整体让位（返回空对），收起自动恢复；“收回回退”由重算天然达成——被收回者出列后，余下的次新/更早者自动顶上空位。
- **宽度估算**（`SummaryChipMetrics.estimatedWidth(for:)`）：AppKit 文本度量 + 符号位（14）+ 横向内边距（20）+ 余量（6），**宁宽勿裁**，封顶 `maxWidth = 180`（超长由视图截断兜底）。主文案 12pt semibold、副文案 11pt 常规，与 SwiftUI 渲染同字体规格；副文案渲染在同一条文本行内，估算必须连同间距计入（不估算它芯片就会裁到副文案）。宽度由控制器按文案估算并同步带宽，不走视图逐帧回写，避免「测量 → 重建」环路。
- **几何与刷新纪律**：估算宽度写入 `uiState.summaryLeftWidth / summaryRightWidth`，`syncSummaryGeometryMirrors()` 把**生效宽度**（`effectiveSummary*Width`：抽屉展开或无可见摘要 = 0）推到各 pair 几何镜像并重摆热区窗口；带宽取两侧较大值 `sideSummaryBand = max(leftSummaryBand, rightSummaryBand)`（`NotchGeometry` 摘要带宽节），无摘要一侧的余量落在面板外端，刘海恒为带宽中心。摘要本身引起带宽变化时，几何同步沿既有紧凑链路（镜像 + 重摆）走，不要求再走 `refreshCompactGeometry()`/`rebuildContent()` 全量路径。
- **动画纪律**：芯片出现/更新/移除的过渡动画一律发生在既有窗口**内容内**（`.transition` 进出场、进度原位刷新），窗口 frame 不参与动画（旧活动岛 frame 动画是历史事故教训）；摘要芯片纯展示、点击穿透（点击 = 展开抽屉的统一语义，不抢焦点）。
- **协议纪律**：`showActivitySummary` / `removeActivitySummary(id:)` 必须保持为 `HostController` **协议要求**（extension 只提供默认实现），否则宿主经存在类型分发会被静态遮蔽（同 settingsView 家族坑）。
- **回归**：`ActivitySummaryTests`（可见对/抽屉让位/同 id 覆盖不换位/收回回退/宽度估算）、`NotchGeometryTests`（摘要带宽对称与芯片矩形、芯片侧图标外移、激活热区含带宽）。

参考实现：`PomodoroPlugin`（`pomodoro.summary`：会话运行中提交「阶段 + 剩余 + 进度」，停止收回）、`MediaControlsPlugin`（`media-controls.summary`：播放中提交「曲名 + 艺术家 + 进度」，暂停置态、停止收回）。
