# 测试指南 — 领域约定

> [AGENTS.md](../../AGENTS.md) 的领域子文档：测试 target 全量清单与测试注意事项。

## 运行

```bash
./scripts/build.sh test                  # 全量（tuist generate + xcodebuild test）
./scripts/build.sh test <套件/用例>       # 单文件/单用例调试（映射 -only-testing）
```

## 先 `test` 再 `dev`：组装好的 .app 会让测试宿主崩溃

`build.sh dev` 把各插件组装成 `.bundle` 放进 `Build/Products/Debug/NotchCenter.app/Contents/PlugIns`，而测试 target 以**同一个目录**里的 `NotchCenter.app` 作 `TEST_HOST`，同时又把插件 dylib 直接链进测试包。于是同一个 ObjC 类同时存在于 dylib 与 bundle 里，测试宿主启动即崩：

```text
objc[NNN]: Class XxxPlugin is implemented in both .../libXxxPlugin.dylib and
           .../NotchCenter.app/Contents/PlugIns/XxxPlugin.bundle/Contents/MacOS/XxxPlugin
Testing failed: Early unexpected exit, operation never finished bootstrapping
```

**这是环境顺序问题，不是代码问题**（`build.sh test` 全绿、`build.sh dev` 也全绿，只是不能在同一产物目录上共存）。验证顺序固定为**先 `test` 后 `dev`**；若已经跑过 `dev`，先

```bash
rm -rf .build/xcode/Build/Products/Debug/NotchCenter.app
```

再跑 `test`。排查时 `grep -c "implemented in both"` 的输出若非 0，就是这个坑。

## 覆盖清单

### Kit 与基础设施

- `APIVersionTests` — 语义版本与 API 版本区间。
- `StateStoreTests` — 插件隔离键值存储，含 placementScope 实例作用域隔离。
- `PluginManagerTests` — 用纯 Info.plist fixture bundle，不加载真实代码。
- `LaunchdControlKitTests` — 命令字符串构造与 plist 读写生成，不真跑 launchctl。
- `EditMenuInstallerTests` — 隐藏主菜单接线：标准编辑快捷键的 nil-target 条目与键等价物。
- `ReadmeMarkdownTests` — 插件管理窗口插件文档：Markdown 块级解析 / bundle 内 README 读取与缺失兜底。
- `PluginServicesHookTests` — 服务钩子经存在类型分发到遵守类重写的回归。

### 布局引擎与几何

- `LayoutEngineTests` — 含“编辑模式契约”、“配置项：最小行数 / 最小列数”、“列双向扩大（左扩）”、“容量缩小修复”等节。
- `MinimumGridSizePersistenceTests` — 最小行列写盘与解码夹紧、旧 JSON 缺键回落。
- `DragReorderReproTests` — 随机拖拽不变量重放 / 粘连对回归 / 损坏布局自愈 / 留白保护 / 列跨度不变量。
- `DragUnificationTests` — 占位框落点 == 提交落点 / 预览 == 提交逐块严格相等。
- `ResizeHysteresisTests` — 缩放量化死区 / 边界抖动不翻转 / 跨档跳转 / 按下不缩小。
- `DrawerGestureMathTests` — 拖拽位移→格 / 缩放位移→候选跨度 / 补偿偏移。
- `DrawerGridGeometryTests` — 坐标互逆往返 / 容量夹紧 / 分数步长容差 / 容器高度按最小行数兜底。
- `DrawerDropPolicyTests` — 落点区域判定。
- `DrawerLayoutMetricsTests` — 尺寸指标 / 左列约束 / 屏幕封顶 / 最小行列夹紧同源。
- `DrawerInteractionStateTests` — 阶段迁移 / 松手顺序 / 真引擎 200 步随机拖拽预览==提交。
- `LayoutPerformanceTests` — 抽屉页面与布局性能基线（`measure` + 宽松预算闸门）：拖拽/缩放预览每帧路径、推挤与压实、提交落盘、启动净化、rebuildContent 引擎查询、滑动判据、网格渲染换算、胶囊槽位数学。
- `DrawerStayConditionsTests` — 收起守卫逐字段。
- `ColumnRangeSliderTests` — 双游标列数滑条：值↔分数映射与半档量化 / min 游标值域恒非空与显示夹取 / 游标选择平手悬置按位移方向分工 / 标签防撞排布。

## 注意事项

- 涉及 `pmset` / 休眠的逻辑测试应确保**不真正改变系统睡眠状态**。
- 涉及 AppKit 窗口/事件的逻辑依赖 App 运行环境，注意保持 `@MainActor` 测试隔离（`setUp`/`tearDown` 是非隔离上下文，不要在里面改 @MainActor 属性）。
- **进程级单例读到的是开发机上的真实偏好**：测试以宿主 App 为 `TEST_HOST`（见 Project.swift），`UserDefaults.standard` 就是用户在「设置 → 布局」里调过的那一份，`GridMetricsStore.shared` 因此可能不是出厂格（例如最小档 75×60）。凡用像素夹具（`fixtureBox`，基准 = 出厂 150×120）或读 `NotchGridMetrics` 的套件，必须在 `setUp` 里 `pinGridMetricsToFixtureDefaults()` 把指标钉住（用例结束自动还原，见 `GridMetricsTestSupport.swift`）——否则"small = 1×1"会被换算成别的跨，几何断言翻倍、`resizeDrawerBlock` 按换算后的档位盒拒缩放，且失败面随套件执行顺序漂移。共享单例同理**只能改完原样还原**：`resetToDefaults()` 会删掉用户持久化的设置（`GridMetricsStoreTests.testGridMetricsForwardsToSharedStore` 的历史写法，已改为快照还原）。
