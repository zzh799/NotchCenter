# 插件开发指南

> 版本：1.0
> 日期：2026-08-24
> 适用范围：所有 NotchCenter 插件的通用开发流程（入口协议、块模型、登记与构建验证）。
> 服务控制类插件（launchd 服务卡）的专门内容见 [`服务控制类插件开发指南.md`](服务控制类插件开发指南.md)。

---

## 1. 插件是什么

NotchCenter 的核心只承担基础设施（刘海交互、窗口管理、插件加载与生命周期、布局引擎、状态存储、插件管理），一切业务功能都是**第三方可同等替换的插件**。内置官方插件（`Plugins/` 目录）与第三方插件走完全相同的加载路径，没有特权。

插件是 `.bundle`（动态库 + Info.plist 元数据），宿主经 `NSPrincipalClass` 实例化主类。身份信息全部来自 bundle 的 Info.plist（文档 §4.1），协议不重复要求 pluginID 等属性。

## 2. 入口协议（NotchCenterKit）

```swift
@objc(<Name>Plugin)   // 必须！原因见 §6 常见坑
public final class <Name>Plugin: NSObject, NotchCenterPlugin, NotchCenterPluginServices {
    static var blocks: [NotchBlock] { ... }        // 块类型清单（静态，实例化前即可读取）
    init()                                          // 无参构造，宿主调用
    func attachServices(stateStore: StateStore, hostController: any HostController)  // 服务注入
}
```

| 成员 | 说明 |
|---|---|
| `static var blocks` | 插件提供的块清单。块分两类：`BlockKind.compact`（刘海两侧紧凑图标）与 `.drawer`（抽屉网格块） |
| `attachServices` | 可选钩子（`NotchCenterPluginServices`）：宿主在实例化、启用/禁用后注入作用域 `StateStore` 与 `HostController`。无法注入时插件仍可运行 |
| `pluginWasDisabled()` | 可选钩子：插件被禁用时调用。禁止在此卸载 bundle（文档 §3.4）；持有浮窗等额外窗口的插件在这里关闭它们 |
| `settingsView` | 可选设置界面（文档 §4.7）。宿主统一经 Kit 的 `SettingPopover` 浮窗展示：布局编辑模式下，紧凑图标右上角 / 抽屉块左上角的齿轮按钮触发。返回 nil 时这些入口都不出现 |
| `menuItems` | 可选状态栏菜单贡献（文档 §4.8），最多 3 项 |

**注意**：`settingsView` / `menuItems` 必须声明为协议**要求**（而非仅 extension 默认实现）。宿主通过存在类型 `any NotchCenterPlugin` 访问，Swift 只按 witness table 分发；纯 extension 成员会被静默忽略（历史 bug：设置界面与菜单项全部失效）。

## 3. 块模型与上下文

### 尺寸

抽屉块声明**物理像素三档**（单位 pt），与用户格子尺寸无关：

```swift
NotchBlock(
    id: "media.controls",
    displayName: ...,
    kind: .drawer,
    minSize: BlockPixelSize(width: 300, height: 240),          // 最小：全局下限 75×60
    maxSize: BlockPixelSize(width: 600, height: 240),          // 最大
    recommendedSize: BlockPixelSize(width: 300, height: 240),  // 推荐：宿主落位默认用
    ...
)
```

- 规则：三档齐全、逐轴 `min ≤ recommended ≤ max`、min ≥ 75×60；compact 块不得声明三档。
- 宿主按**当前用户格子尺寸**把三档换算成允许格跨盒 `[min…max]`（`NotchBlock.sizeBox`）：min 向上取整（物理 ≥ min）、max 向下取整（物理 ≤ max，至少 1 格）、recommended 就近取整夹进盒内。
- 换算不含格间间距（组件像素 = 格子之和）。用户把格子调大导致 1×1 都超 max 时 1×1 兜底显示，存量块不动、再拖拽按新边界钳制——**组件要按任意盒内整数跨做自适应版式**，不要假设固定档位。
- 存量官方插件迁移公式：旧跨度 × 默认格（150/120）→ 像素（如旧 2×2 → 300×240）。

### 打包期最小尺寸遮挡校验（probes）

官方 drawer 块**必须**声明 `probes`（门禁强制，缺失即失败）：

```swift
NotchBlock(
    id: "media.controls",
    ...
    probes: { info in mediaControlLayoutProbes(for: info.frame.size) },
    makeView: { ... }
)
```

- `probes` 回调输入 `BlockLayoutInfo`，输出关键 UI 区的 `BlockProbe { id, rect }` 矩形  （块本地坐标，原点 = 内容区左上）；打包校验时宿主以 `minSize` 作为 frame 调用。
  **探针只准依赖 `frame.size`（像素）**，不得依赖 `size/widthColumns/heightRows`——打包期  没有网格跨度上下文（恒 nil），也不要自己换算格子。
- 探针语义 = 意图契约：区带须由与块视图**同一套布局常量**推导（行高、内边距、字号等，  改动布局时同步）。校验器按内容盒 = minSize 做两类纯几何检查：
  - **越界**：探针 rect 越出 minSize 盒 → 最小尺寸下内容会伸到邻居块（宿主卡片不裁切），报 `probeOutsideContent`；
  - **自叠**：两个探针 rect 相交 → 组件内部关键区互相覆盖，报 `probesOverlap`。
- 布局提示：
  - 固定堆叠区带（顶栏/行/按钮）按自然行高自上而下排成互不重叠的矩形，最末区带并入底部内边距，让"minSize 矮于总需求"精确触发越界；
  - 整面自适应/内部滚动的容器（ScrollView、ViewThatFits、自适应网格）结构上不会溢出邻居，声明一个内容区探针即可（内边距值即其缩进）。
- 本地验证：`./scripts/build.sh verify-sizes`（几何判定单测 + 全部官方抽屉块门禁）；`package` 打包前默认预检同一门禁（`--skip-size-check` 逃生）。机制与边界见 Agent Note  `2026-09-07-block-min-size-occlusion-verification`。

### 大组件与添加落点偏好（`BlockPlacement`）

**抽屉块没有"独占整页"这种种类**（原 `BlockKind.page` 已于 2026-09-10 撤销）：所有抽屉块同规则、同权，可与任意块同页共存、可拖动缩放重排。若你的组件"一个就占掉大半页"，希望用户添加它时不要塞进当前页的缝里，声明 `placement`：

```swift
NotchBlock(
    id: "pomodoro.page",
    displayName: ...,
    kind: .drawer,                                            // 就是普通抽屉块
    minSize: BlockPixelSize(width: 300, height: 240),
    maxSize: BlockPixelSize(width: 900, height: 600),
    recommendedSize: BlockPixelSize(width: 600, height: 360),
    placement: .newPageWhenOccupied,                          // 当前页被占用则另开一页
    symbolName: "timer.circle",                               // 落位时补为该页默认图标
    probes: { info in Self.myLayoutProbes(for: info.frame.size) },
    makeView: { context in AnyView(PomodoroPageView(context: context)) }
)
```

- **`placement` 只影响"从目录添加那一刻"落在哪一页**：`.autoGrid`（默认）在当前页自动寻空位；`.newPageWhenOccupied` 在当前页为空时就地占用，否则新开一页（9 页满且当前页非空即失败提示，宿主不搜刮其它空页、不自动清理任何页）。
- **落位之后无任何限制**：该块可拖动、可缩放、可跨页搬移、可参与一键重排、可与任意块同页共存。想要"独占一页"的语义，宿主不再提供——页数是 9 页上限内的共享资源。
- **渲染契约与普通抽屉块完全一致**：统一套 `BlockCard`、统一进宿主抽屉 `ScrollView`，
  **不要自己再套一层 `ScrollView`**（会出现双层滚动）；齿轮、✕、缩放握把由宿主统一绘制。
- **`probes` 一律必须声明**（官方块门禁强制）：大组件同样可能与邻居同页，不存在豁免。纵向内容多的视图建议只把"必须完整可见"的区带声明为探针，允许中段自适应/被压缩，避免在 `minSize` 下越界。
- **实例身份**：`BlockContext.placementID` 与其它抽屉块一致；状态一律走 `stateStore`（按 `(pluginID, blockID, placementID)` 隔离）。
- 参考实现：`Plugins/PomodoroPlugin`（`pomodoro.page`：大计时器 + 今日节奏 + 历史回顾）。

### 运行时上下文
宿主构建每块屏的视图树时把 `BlockContext` 注入块视图：

| 字段 | 说明 |
|---|---|
| `pluginID` / `blockID` | 身份；`placementID` 标识一次摆放（同一块可摆多处，每处一个 placement） |
| `stateStore` | 插件隔离键值存储，持久化到 `PluginData/<pluginID>/`（原子写）。插件状态一律走它，不要自己写文件到别处 |
| `hostController` | 宿主控制 API：展开/收起抽屉、编辑模式、刷新紧凑区、活动摘要通道（`showActivitySummary` / `removeActivitySummary`，见下） |
| `layoutInfo` | 当前布局信息（区域、frame、是否编辑态等），随布局变化由宿主推送 |

插件进入活动状态（计时中、正在播放等）可经 `hostController.showActivitySummary(_:)` 提交一行「图标 + 文案 + 迷你进度」摘要，宿主在刘海紧凑带内渲染（**不新建窗口、不遮挡屏幕**）；同 id 覆盖更新（不换位）、结束/禁用时经 `removeActivitySummary(id:)` 收回。提交/收回接口是协议**要求**；内容变化节流（如整秒）由插件自控，宿主做等值短路。契约与纪律见 [`紧凑区与活动摘要`](agents/紧凑区与活动摘要.md)；参考实现：`PomodoroPlugin`（`pomodoro.summary`）、`MediaControlsPlugin`（`media-controls.summary`）。

### 注册快捷按钮（快速区与「快捷按钮盒」双落位）

一键入口统一建模为**快捷按钮** `QuickAction`：同一按钮既可放进快速区（刘海带）也可收纳进「快捷按钮盒」，宿主统一标准样式渲染（Kit `QuickActionTile`），插件**不再需要注册自带视图的紧凑块**。在主类上实现 `quickActions`（协议要求 + 默认空）：

```swift
public var quickActions: [QuickAction] {
    // 缓存同一批实例（identity 稳定）；宿主在启用时收集一次，勿每次 new。
    QuickAction(
        id: "<plugin>.<action>",            // 全局唯一，冲突先到先得
        displayName: L("…"), systemImage: "…",
        kind: .toggle,                      // 或 .action
        requiresConfirmation: true,         // 服务启停等重动作必开
        isActive: store.isOn,               // toggle 初值
        execute: { [weak store] in store?.toggle() }
    )
}
```

要点：宿主 enable 后注册、disable 前注销；开关类动作把自身 store 的状态变化同步到 `QuickAction.isActive`（按钮据此点亮）。渲染/点击/确认由宿主统一负责，插件无需关心。官方约定：id **沿用旧紧凑块 id**（如 `notes.compact`）使旧布局槽位零迁移；原默认进快速区的动作设 `defaultInStrip: true` 进入首启默认布局；打开型入口（如展开抽屉）以 `execute` 调 `hostController.expandDrawer()` 忠实复刻点击语义。完整契约与纪律见 [`快捷按钮盒 Agent Note`](agent-notes/implemented/2026-09-05-quick-button-box.md)。

第三方若仍想提供自带视图的紧凑块（如动态角标），照旧注册 `kind: .compact` 的块即可（宿主按块渲染、目录以块卡展示）；块卡与动作合一可用可选 `sourceBlockID`（只在「动作点击 ≡ 块点击」时标注）。

## 4. 新增插件：步骤

### Step 1 建目录写代码

```text
Plugins/<Name>Plugin/
├── Plugin.plist
├── README.md                 # 插件说明文档（可选）：build.sh 随包复制进 bundle，
│                             # 插件管理窗口详情区据此展示
└── Sources/
    ├── <Name>Plugin.swift     # 主类（§2 入口模式）
    └── ...
```

参照现有插件的入口模式：通用业务插件看 `NotesPlugin`（StateStore 持久化 + 编辑器视图）；launchd 服务控制看 DshPlugin / CalibrePlugin。

### Step 2 写 Plugin.plist（唯一登记处）

根目录 Project.swift 与 scripts/build.sh 都从 `Plugins/` 目录自动发现插件，新增插件不需要改任何列表或 case 分支：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>PluginID</key>
  <string>com.zhouzihang.notchcenter.<name></string>
  <key>Version</key>
  <string>1.0.0</string>
  <key>DisplayName</key>
  <string><显示名></string>
  <key>Description</key>
  <string><一句话描述></string>
  <!-- 可选字段：
       Dependencies   额外本地产品数组（如 ["LaunchdControlKit"]；NotchCenterKit 隐式注入）
       NSPrincipalClass  缺省等于文件夹名
       APIVersionRange   缺省 1.0..<2.0 -->
</dict>
</plist>
```

规则：

- 必填四项缺一不可，`PluginID` 全局唯一（脚本会校验，重复/缺失直接报错退出）。
- 额外依赖需在根 Project.swift 的 `knownExtraDependencies` 白名单里登记，并在 `extraDependency(_:)` 补对应依赖映射（SPM 包产品用 `.package(product:)`，本地 target 用 `.target(name:)`）。
- **PluginManager 无需改动**：内置（`Contents/PlugIns/`）插件自动发现、默认启用并持久化。

### Step 3 构建与验证

```bash
./scripts/build.sh test               # 全量测试
./scripts/build.sh dev                # 构建 + 组装 .bundle 进产物 .app，确认产出与元数据正确
./scripts/build.sh run                # 启动宿主 .app，编辑模式添加块，冒烟验证
```

## 5. 并发约定

- Kit 与 store 的公共 API 都是 `@MainActor`（文档 §4.9）；UI 与状态更新必须回主线程，`@Published` 属性驱动 SwiftUI 刷新。
- 插件内部的后台任务自行处理：同步阻塞调用用 `Task.detached` 丢后台，结果回主线程。
- 跨线程共享可变状态需要显式隔离（参考 `Plugins/NotesPlugin/Sources/NotesImageStore.swift` 的 `@unchecked Sendable` + `NSLock` 模式）。

## 6. 常见坑

- **主类必须 `@objc(<Name>Plugin)`**：SPM 动态库启用 library evolution，无显式 `@objc` 时运行时类名是 mangled 形式，`NSPrincipalClass` 找不到。新增插件时最易漏。
- **rpath 上溯 4 级**：bundle 内可执行文件位于 `Contents/PlugIns/<Name>.bundle/Contents/MacOS/`，相对宿主 `Frameworks/` 恰好 4 级（`@executable_path/../../../../Frameworks`）。新 target 由根 Project.swift 自动生成统一 `LD_RUNPATH_SEARCH_PATHS`，手工建 target 时照抄。
- **插件块内不得让隐藏窗口复活**：宿主把同一份 block view 塞进每块屏的抽屉树，按 placementID 共享的交互状态会被多屏实例并发 bind。约束：绑定入口必须拒绝“隐藏窗口候选覆盖可见现任”；任何聚焦/激活调用前必须 `window.isVisible` 防护，否则已收起的抽屉会被重新拉上屏（表现为“另一块屏多出一块面板”）。
- **UI 字符串用英文、注释用中文**，与仓库整体约定一致。
- **抽屉强制深色**（`.environment(\.colorScheme, .dark)`），背景接近纯黑半透明；改动视觉保持“贴近刘海”的观感（见 docs/DESIGN.md）。
