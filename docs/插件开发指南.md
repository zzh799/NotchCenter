# 插件开发指南

> 版本：1.0
> 日期：2026-08-24
> 适用范围：所有 NotchCenter 插件的通用开发流程（入口协议、块模型、登记与构建验证）。
> 服务控制类插件（launchd 服务卡）的专门内容见 [`服务控制类插件开发指南.md`](服务控制类插件开发指南.md)。

---

## 1. 插件是什么

NotchCenter 的核心只承担基础设施（刘海交互、窗口管理、插件加载与生命周期、布局引擎、状态存储、插件管理），一切业务功能都是**第三方可同等替换的插件**。内置官方插件（`Plugins/` 目录）与第三方插件走完全相同的加载路径，没有特权。

插件是 `.bundle`（动态库 + Info.plist 元数据），宿主经 `NSPrincipalClass` 实例化主类。身份信息全部来自 bundle 的 Info.plist（文档 §4.1），协议不重复要求 pluginID 等属性。

## 2. 入口协议（NotchCenterKit）

```swift
@objc(<Name>Plugin)   // 必须！原因见 §6 常见坑
public final class <Name>Plugin: NSObject, NotchCenterPlugin, NotchCenterPluginServices {
    static var blocks: [NotchBlock] { ... }        // 块类型清单（静态，实例化前即可读取）
    init()                                          // 无参构造，宿主调用
    func attachServices(stateStore: StateStore, hostController: any HostController)  // 服务注入
}
```

| 成员 | 说明 |
|---|---|
| `static var blocks` | 插件提供的块清单。块分两类：`BlockKind.compact`（刘海两侧紧凑图标）与 `.drawer`（抽屉网格块） |
| `attachServices` | 可选钩子（`NotchCenterPluginServices`）：宿主在实例化、启用/禁用后注入作用域 `StateStore` 与 `HostController`。无法注入时插件仍可运行 |
| `pluginWasDisabled()` | 可选钩子：插件被禁用时调用。禁止在此卸载 bundle（文档 §3.4）；持有浮窗等额外窗口的插件在这里关闭它们 |
| `settingsView` | 可选设置界面（文档 §4.7），返回 nil 时插件管理窗口只显示元数据 |
| `menuItems` | 可选状态栏菜单贡献（文档 §4.8），最多 3 项 |

**注意**：`settingsView` / `menuItems` 必须声明为协议**要求**（而非仅 extension 默认实现）。宿主通过存在类型 `any NotchCenterPlugin` 访问，Swift 只按 witness table 分发；纯 extension 成员会被静默忽略（历史 bug：设置界面与菜单项全部失效）。

## 3. 块模型与上下文

### 尺寸

`BlockSize` 是预设（`.small` 1×1 / `.medium` 2×1 / `.wide` 4×1 / `.large` 2×2 / `.extraLarge` 4×2）；真实约束是块的 `supportedSpans`（由 `supportedSizes` 派生 + `supportedGridSpans` 自由跨度）。新增尺寸能力时扩展 `supportedGridSpans`，不要堆预设。

### 运行时上下文

宿主构建每块屏的视图树时把 `BlockContext` 注入块视图：

| 字段 | 说明 |
|---|---|
| `pluginID` / `blockID` | 身份；`placementID` 标识一次摆放（同一块可摆多处，每处一个 placement） |
| `stateStore` | 插件隔离键值存储，持久化到 `PluginData/<pluginID>/`（原子写）。插件状态一律走它，不要自己写文件到别处 |
| `hostController` | 宿主控制 API：展开/收起抽屉、编辑模式、刷新紧凑区 |
| `layoutInfo` | 当前布局信息（区域、frame、是否编辑态等），随布局变化由宿主推送 |

## 4. 新增插件：步骤

### Step 1 建目录写代码

```
Plugins/<Name>Plugin/
├── Plugin.plist
└── Sources/
    ├── <Name>Plugin.swift     # 主类（§2 入口模式）
    └── ...
```

参照现有插件的入口模式：通用业务插件看 `NotesPlugin`（StateStore 持久化 + 编辑器视图）；launchd 服务控制看 DshPlugin / CalibrePlugin。

### Step 2 写 Plugin.plist（唯一登记处）

Package.swift 与 Scripts/build.sh 都从 `Plugins/` 目录自动发现插件，新增插件不需要改任何列表或 case 分支：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>PluginID</key>
  <string>com.zhouzihang.notchcenter.<name></string>
  <key>Version</key>
  <string>1.0.0</string>
  <key>DisplayName</key>
  <string><显示名></string>
  <key>Description</key>
  <string><一句话描述></string>
  <!-- 可选字段：
       Dependencies   额外本地产品数组（如 ["LaunchdControlKit"]；NotchCenterKit 隐式注入）
       NSPrincipalClass  缺省等于文件夹名
       APIVersionRange   缺省 1.0..<2.0 -->
</dict>
</plist>
```

规则：

- 必填四项缺一不可，`PluginID` 全局唯一（脚本会校验，重复/缺失直接报错退出）。
- 额外依赖需在 Package.swift 的 `knownExtraProducts` 白名单里登记；包引用名与产品名不一致的还要补 `extraPackageNameByProduct` 映射。
- **PluginManager 无需改动**：内置（`Contents/PlugIns/`）插件自动发现、默认启用并持久化。

### Step 3 构建与验证

```bash
swift build && swift test
./Scripts/build.sh dev                # 组装 .bundle 到 dev PlugIns，确认产出与元数据正确
swift run NotchCenter                 # 编辑模式添加块，冒烟验证
```

## 5. 并发约定

- Kit 与 store 的公共 API 都是 `@MainActor`（文档 §4.9）；UI 与状态更新必须回主线程，`@Published` 属性驱动 SwiftUI 刷新。
- 插件内部的后台任务自行处理：同步阻塞调用用 `Task.detached` 丢后台，结果回主线程。
- 跨线程共享可变状态需要显式隔离（参考 `Plugins/NotesPlugin/Sources/NotesImageStore.swift` 的 `@unchecked Sendable` + `NSLock` 模式）。

## 6. 常见坑

- **主类必须 `@objc(<Name>Plugin)`**：SPM 动态库启用 library evolution，无显式 `@objc` 时运行时类名是 mangled 形式，`NSPrincipalClass` 找不到。新增插件时最易漏。
- **rpath 上溯 4 级**：bundle 内可执行文件位于 `Contents/PlugIns/<Name>.bundle/Contents/MacOS/`，相对宿主 `Frameworks/` 恰好 4 级（`@executable_path/../../../../Frameworks`）。新 target 由 Package.swift 自动生成统一 linkerSettings，手工建 target 时照抄。
- **插件块内不得让隐藏窗口复活**：宿主把同一份 block view 塞进每块屏的抽屉树，按 placementID 共享的交互状态会被多屏实例并发 bind。约束：绑定入口必须拒绝“隐藏窗口候选覆盖可见现任”；任何聚焦/激活调用前必须 `window.isVisible` 防护，否则已收起的抽屉会被重新拉上屏（表现为“另一块屏多出一块面板”）。
- **UI 字符串用英文、注释用中文**，与仓库整体约定一致。
- **抽屉强制深色**（`.environment(\.colorScheme, .dark)`），背景接近纯黑半透明；改动视觉保持“贴近刘海”的观感（见 docs/DESIGN.md）。
