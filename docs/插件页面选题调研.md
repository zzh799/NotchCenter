# 插件页面选题调研：能力边界、竞品地形与候选清单

> 日期：2026-09-10
> 范围：`BlockKind.page`（整页块）能力上线后，NotchCenter 还能做哪些插件页面

> 相关：整页块能力见 [Agent Note](agent-notes/implemented/2026-09-10-plugin-page-blocks.md)，视觉与形态规范见 [DESIGN.md](DESIGN.md)，开发流程见 [插件开发指南](插件开发指南.md)

## 0. 结论先行

整页块把刘海抽屉从「网格里的若干张小卡」升级成「可以钉一块专属看板」的形态，这是本项目相对同类产品最锋利的一处空白：竞品要么是单体应用（NotchNook、Alcove），要么才刚刚把「扩展系统」写进路线图（Boring Notch、Droppy），而 NotchCenter 从第一天就是插件宿主，整页块等于给「一个插件 = 一个完整页面」这条生态路线补上了最后一块拼图。

一句话结论：**先做能复用现有引擎的「深度视图页」把形态打透，再用开发者/AI 场景建立竞品没有的护城河，最后靠插件生态把长尾填满。**

八条建议首批落地（P0）：音乐中心页、系统监控仪表盘页、剪贴板库页、日历与日程页、待办与提醒页、控制中心开关页、AI 编码助手监控页、天气页。

## 1. 能力边界：插件页面能做什么、不能做什么

### 1.1 渲染契约（决定形态上限）

整页块独占一整个抽屉页，同页不得再有任何其它抽屉块；页面主体满血铺满内容区，不套 `BlockCard`、不进宿主的抽屉 `ScrollView`，滚动与内边距由插件自管；左上设置齿轮、右下缩放握把与普通抽屉块一致，顶栏与分页胶囊仍归宿主。尺寸仍走像素三档（min / recommended / max），列跨度恒夹在 `[minimumColumnCount(), effectiveMaxColumns()]`，原点恒 `(0,0)`，可缩放不可拖动、不可跨页搬运。

由此得到的实际画布：宽度约 480–540 pt（多显示器/无刘海屏回退到顶部中央），高度上限约 `screenHeight - 84`，典型一次展开能看到 400–900 pt 高。**这是一块「约 500 × 700 pt 的竖版看板」**，不是全屏窗口，也不是能横向铺开的多栏桌面。

### 1.2 四条硬约束

- **页数是稀缺资源**：抽屉最多 9 页，整页块之间互相挤占。这决定了「值不值得做成整页」必须严格筛选，不能什么都页面化。
- **不引入新的 SPM 远程依赖**：网络类需求用 `URLSession` 手写；需要第三方库的（如终端模拟）只能走 `Vendor/` 受控引入，成本显著抬高。
- **私有 API 只在已验证的运行时接触面内使用**：现状是 `MediaRemote`（`dlopen`/`dlsym`）。任何新增私有 API 都要评估上架与稳定性风险。
- **UI 一律本地化**（en 基准 + zh-Hans 键集一致）、Swift 6 严格并发、`@MainActor` 隔离、视觉引用 `NotchTokens`——这些是插件的既有义务，页面化不豁免。

### 1.3 形态选型：什么时候才该做整页

同一条需求可以有四种呈现形态，选错会导致「页数被浪费」或「信息密度不足」。判定顺序如下：

| 形态 | 承载什么 | 典型信号 | 现有样例 |
|---|---|---|---|
| 活动摘要（紧凑带芯片） | 进行中的瞬时状态，瞥一眼 | 「现在正在发生什么」、可被一句话概括、有进度 | 播放中、番茄计时中 |
| 快捷按钮（快速区/按钮盒） | 一键触发，无内容呈现 | 只有动作、没有信息 | 防休眠开关、展开抽屉 |
| 抽屉块（网格卡） | 常驻可并列的中等密度信息 | 需要和其它块同屏、可扫视 | 系统监控、剪贴板、亮度 |
| **整页块** | 单任务沉浸、信息层次深、需要大画布 | 需要滚动、需要多分区、需要「专注做一件事」 | 番茄钟看板 |

一条经验法则：**当需求出现「同屏要看到 ≥3 个信息区」或「需要纵向滚动」时，才考虑整页；否则先用抽屉块试水。** 反过来，如果一个需求已经在抽屉块里被证明「空间不够用」，那就是页面化的最强信号——现有的剪贴板历史、系统监控、媒体控制三个块都属于这一类。

## 2. 现状盘点：12 个官方插件覆盖了什么

| 插件 | 形态 | 覆盖能力 | 页面化潜力 |
|---|---|---|---|
| Notes | 紧凑 + 抽屉块 | 多标签 Markdown 笔记 | 低（编辑器已够用） |
| Scratchpad | 紧凑 + 抽屉块 | 文件暂存（只存引用） | 低 |
| Caffeinate | 紧凑 + 快捷按钮 | 防休眠 | 低（动作型） |
| Pomodoro | 抽屉块 + **整页块** | 专注计时 + 评分 + 历史 | 已页面化（唯一活样例） |
| MediaControls | 抽屉块 + 活动摘要 | 系统 Now Playing 控制 | **高**（歌词/队列需大画布） |
| ClipboardHistory | 紧凑 + 抽屉块 | 纯文本剪贴板历史（50 条） | **高**（富预览/搜索/置顶区） |
| Display | 抽屉块 ×2 | DDC/CI 外接屏亮度 | 中（可扩分辨率/排列） |
| Dsh / Calibre | 抽屉块 | launchd 服务启停（共用 LaunchdControlKit） | 低（功能已完整） |
| OpenCodeUsage | 抽屉块 | OpenCode 用量窗口 + 余额 | 中（可扩多源用量/成本） |
| SystemMonitor | 抽屉块 ×5 | CPU/内存/磁盘/网络/总览 | **高**（仪表盘/进程表） |
| QuickButtonBox | 抽屉块 | 快捷按钮收纳宫格 | 低（是基础设施） |

**读出来的空白**：现有覆盖集中在「工具型」和「系统型」，**日程/媒体深度/信息消费/AI 协作/健康**五条线几乎是空的，而这几条恰好是竞品的主战场。

## 3. 竞品地形

### 3.1 刘海类竞品（直接竞争）

- **NotchNook**（$25 买断 / $3 月，最老牌）：媒体控制、日历、Shortcuts 小组件、文件托盘 + AirDrop、摄像头镜像、HUD 替换、GIF 自定义、计时器、待办小组件、笔记。
- **Boring Notch**（免费开源，社区最活跃）：媒体 + 可视化 + 同步歌词、日历、提醒、摄像头镜像、充电指示、文件托盘、HUD 替换；社区分支已补上剪贴板历史、番茄钟；**路线图明确写着「Extension system」和天气、锁屏小组件**。
- **Alcove**（$14.99，「少即是多」的标杆）：媒体 + 可视化、音量/亮度 HUD、电池与充电提醒、日历速览、锁屏 Live Activities、滑动手势。
- **Atoll**（免费开源）：系统监控（CPU/GPU/网络）、剪贴板历史、计时器、摄像头镜像、终端、锁屏小组件——**唯一把系统监控做成卖点的刘海应用**。
- **DynamicLake Pro**（$13.99）：通知镜像（iMessage/WhatsApp/Telegram 内联快回）、拖放、文件转换、通话、AirDrop、计时器、miniLake 紧凑模式。
- **Droppy**（$9.99）：文件架、剪贴板、媒体中心（歌词 + Up Next）、通知镜像内联回复，外加二十多个可选扩展「Droplets」——窗口吸附、通用启动器、会议控制、语音转写、文件转换、终端、AI 编码会话 HUD。
- **Seam**（$19.90）：媒体、专注会话、日历、AirPods 指示、电池——主打省电。
- **MacNotch**（$22.99）：19 个可开关模块，独家 **Day Progress（今日时间轴）、Screen Time、健康环 + 护眼、通知内联回复、窗口吸附、PR 审查队列、AI 编码代理监控**。
- **Notchy**（免费）：媒体 + 歌词、剪贴板、速记、番茄钟、HUD、电池、文件架、**OCR**。

### 3.2 菜单栏 / 工具类竞品（能力参照系）

这类不是刘海应用，但它们是「用户愿意为哪些单点能力付费」的最佳证据，也是插件页面的需求池：

- **Raycast**：启动器 + 2000 多个扩展（GitHub/Linear/Jira/Notion/Docker/Brew/翻译/颜色拾取/系统监控/剪贴板），当前 macOS 效率工具的「事实标准」。
- **Bartender 6 / Ice**：菜单栏图标管理、预设、触发器、自定义小组件。
- **Stats / iStat Menus**：CPU/GPU/内存/磁盘/网络/风扇/温度图表。
- **Itsycal / Dato**：菜单栏日历与时间。
- **Maccy / Paste**：剪贴板历史（本地轻量 vs 可视化 + 同步）。
- **One Switch**：深色模式、勿扰、防休眠、AirPods 连接、隐藏桌面等开关抽屉。
- **Hand Mirror / Micro Snitch**：摄像头快速预览 / 摄像头麦克风占用监控。
- **Shottr / CleanShot X**：截图、滚动截图、OCR、取色、标注。
- **AlDente**：电池充电上限与健康。
- **Rectangle**：窗口吸附。
- **Dropover**：文件悬浮暂存架。
- **Meeter**：会议一键加入。
- **AgentBell**：AI 编码代理（Claude Code / Cursor / Codex / Windsurf）状态监控——2026 年新物种。

| 开发者面板（PR/CI） | MacNotch/Raycast | ❌ | 空白 |
| 通知镜像 | DynamicLake/Droppy | ❌ | **高风险，建议不做** |
| 锁屏小组件 | Boring Notch/Alcove | ❌ | 超出宿主能力边界，不做 |

### 3.4 关键洞察

- **同质化重灾区是「媒体 + 文件架 + 日历」三件套**，光靠这些无法差异化。差异化必须来自两类：一是**形态深度**（把某一块做到别人做不到的深度，如系统仪表盘、音乐中心），二是**场景独占**（开发者 / AI 工作流——竞品里只有 AgentBell 和 MacNotch 刚起步，且都是单体应用）。
- **Boring Notch 与 Droppy 都把「扩展系统」写进路线图**，等于市场已经验证「插件化刘海」是方向。NotchCenter 的架构领先在起跑线，缺的只是「值得安装的页面」。
- **9 页上限是硬约束**：应当把整页留给「一天要打开很多次且需要纵深」的场景，而不是把每个功能都做成页。

## 4. 候选插件页面清单

按域分组，每条给出：形态定位、技术依赖与权限、可行性、竞品参照、差异化点。可行性分三档：**低门槛**（复用现有框架/引擎）、**中门槛**（需新框架或权限授权）、**高门槛**（私有 API / 新依赖 / 重权限）。

### 4.1 媒体与内容

**① 音乐中心页（Music Hub）** — *P0*
- 定位：以当前播放为锚的沉浸页——大封面 + 实时滚动歌词 + Up Next 队列 + 可视化频谱；紧凑带继续用活动摘要显示迷你进度，页面是它的「深度视图」。
- 依赖：复用 `MediaRemote`（已封装于 `MediaRemoteSession`）；歌词走公开歌词源（如 LRCLIB，`URLSession`）；可视化用 Accelerate/`Canvas` 绘制。
- 可行性：**低门槛**（现有 `MediaPlayerController` 单例 + 每秒轮询已具备，页面只是换一套视图）。
- 竞品参照：Boring Notch（可视化 + 歌词）、Droppy（歌词 + Up Next）、Notchy——**这是竞品最卷的一块，也是「不做就掉队」的一块**。
- 差异化：把摘要芯片（浅）与整页（深）做成一套连贯的媒体体验，是单体竞品做不到的「同一状态两种粒度」。

**② 播客 / 电台页** — *P2*｜依赖系统 Now Playing + 章节元数据，内容源受限，价值一般，可并入音乐中心页。

**③ RSS / 阅读页** — *P2*｜`URLSession` + `XMLParser`（零依赖可行），但「在刘海里读长文」与场景不匹配，谨慎。

### 4.2 时间与日程

**④ 日历与日程页（Calendar & Agenda）** — *P0*
- 定位：月视图 + 今日/明日事件列表 + 一键加入会议链接。
- 依赖：EventKit（`NSCalendarsFullAccessUsageDescription`，用户授权）。
- 可行性：**中门槛**（框架成熟、无私有 API，成本集中在权限引导与多日历配色）。
- 竞品参照：全员标配（NotchNook / Boring Notch / Alcove / Itsycal / Dato）。
- 差异化：做成「日程 + 待办 + 专注」的今日中枢，而非孤立的日历。

**⑤ 待办与提醒页（Reminders & Tasks）** — *P0*
- 定位：清单式勾选、到期分组、与日历页共享同一「今日」时间轴。
- 依赖：EventKit Reminders（`NSRemindersFullAccessUsageDescription`）。
- 可行性：**中门槛**（与日历页同源，一次授权双份收益）。
- 竞品参照：NotchNook 待办小组件、Boring Notch 提醒、MacNotch 任务。
- 差异化：与番茄钟联动——「把今日待办拖进专注」。

**⑥ 今日时间轴页（Day Progress）** — *P1*
- 定位：把日历事件 + 待办 + 专注记录叠在同一条纵向时间轨上，附就寝标记。
- 依赖：复用 ④⑤ 数据源 + Pomodoro 历史。
- 可行性：**低门槛**（纯聚合视图，无新依赖）。
- 竞品参照：MacNotch 独家模块。
- 差异化：只有插件宿主能做到「跨三个插件聚合数据」，单体应用做这个要重写三遍。

**⑦ 多计时器与世界时钟页** — *P1*｜多路倒计时 + 时区换算，`Foundation` 即可；竞品（Dato/One Switch）需求已验证。

### 4.3 系统与设备

**⑧ 系统监控仪表盘页（System Dashboard）** — *P0*
- 定位：把现有 5 个抽屉块合成一面仪表盘——大图表（CPU/内存/磁盘/网络）+ 进程 Top 列表 + 电池；抽屉块继续做「扫一眼」，页面做「查问题」。
- 依赖：复用 `SystemMonitorPlugin` 的采样引擎（`host_statistics64`/`sysctl`/IOKit）；进程表用 `proc_listallpids` + `libproc`（公开 API）；GPU/风扇温度需 IOAccelerator/SMC（**中高门槛，建议二期**）。
- 可行性：**低门槛（图表与进程表）/ 中高门槛（GPU/SMC）**。
- 竞品参照：Atoll（刘海）、Stats/iStat Menus（菜单栏）。
- 差异化：唯一一家「刘海 + 插件化」的系统监控，且可与服务控制插件联动（进程列表里直接看 dsh/calibre 服务）。

**⑨ 电池与设备状态页** — *P1*｜电池健康/循环/温度（`IOKit`）+ 蓝牙外设与 AirPods 电量（`IOBluetooth`/私有度中等）；竞品 Seam、AlDente 验证需求。

**⑩ 摄像头镜子页（Camera Mirror）** — *P1*
- 定位：一键预览摄像头画面，视频会议前检查仪容。
- 依赖：AVFoundation（`AVCaptureDevice`，需 camera 权限）。
- 可行性：**低门槛**（不到百行代码的量级）。
- 竞品参照：Hand Mirror、NotchNook Mirror、Boring Notch Mirror、Atoll。
- 差异化：低，属「补齐标配」而非「亮点」，但它成本极低、用户感知强，性价比高。

**⑪ 隐私监控页（Privacy Monitor）** — *P1*｜摄像头/麦克风被占用时留痕（竞品 Micro Snitch）；依赖 TCC 与 `AVCaptureDevice` 占用检测，可作为活动摘要的低成本补充。

**⑫ 网络与下载页** — *P2*｜网速图形 + 浏览器下载进度；浏览器下载进度需扩展注入，**不建议**，只做网速部分。

### 4.4 效率与输入

**⑬ 剪贴板库页（Clipboard Library）** — *P0*
- 定位：现有纯文本历史升级为富媒体库——搜索、置顶看板、图片/文件/链接/颜色分类、全文预览。
- 依赖：`NSPasteboard`（已用），图片缩略图复用 Scratchpad 的 QuickLook 缩略图路径。
- 可行性：**低门槛**（数据层与暂停/淘汰策略已存在，主要在视图与类型扩展）。
- 竞品参照：Maccy、Paste、Raycast、Atoll、Droppy、Notchy。
- 差异化：现有 `ClipboardHistoryPlugin` 已是完整实现，页面化是最低成本的高价值升级。

**⑭ 启动器页（Launcher）** — *P1*｜应用/文件/命令快速启动；`NSWorkspace` + Spotlight 元数据查询；竞品 Raycast、Droppy。**注意**：这是「和 Raycast 正面竞争」，价值取决于用户是否愿意把启动动作搬到刘海，建议先做轻量版验证。

**⑮ 截图与 OCR 页** — *P1*｜`ScreenCaptureKit`（需屏幕录制权限）+ `Vision` OCR + 取色，一次性满足 Shottr/Notchy 的核心卖点；**中门槛**（权限较重），但功能密度高。

**⑯ 文件转换页** — *P1*｜图片/视频/PDF 格式转换与压缩；`ImageIO`/`PDFKit`/`AVFoundation` 全公开 API；竞品 DynamicLake、Droppy。

**⑰ 颜色拾取页** — *P1*｜`NSColorSampler` 系统吸管 + 多格式转换 + 色板历史；竞品 Raycast Color Picker，实现成本极低。

**⑱ 文本片段页（Snippets）** — *P2*｜片段库 + 关键词展开；竞品 Raycast Snippets，但「展开」需要全局键盘监听，权限与稳定性成本高。

**⑲ 窗口管理页** — *P2*｜吸附分区/布局预设；`AXUIElement` 控制其它应用窗口，**需辅助功能权限**，竞品 Rectangle/Droppy/MacNotch，实现与维护成本都高。

**⑳ 终端页** — *P2/不建议*｜需要 PTY + 终端模拟器，`SwiftTerm` 属新依赖，与「不引入新 SPM 远程依赖」冲突；竞品 Atoll/Droppy 有，但投入产出比差。

### 4.5 开发者与 AI（差异化主战场）

**㉑ AI 编码助手监控页（AI Agent Monitor）** — *P0*
- 定位：在刘海里盯住 Claude Code / Cursor / Codex / Windsurf 等 AI 代理的任务状态——哪个跑完了、哪个报错了、哪个在等输入；配合活动摘要做「跑完提醒」。
- 依赖：读取各工具本地状态（会话目录、状态文件、hooks/MCP 信号），`Foundation` 文件监听（`FSEvents`/`DispatchSource`）即可，**不读代码与聊天内容**（隐私对齐 AgentBell 的做法）。
- 可行性：**低门槛（架构）／中门槛（适配量）**——难点是各工具状态格式不统一，需要逐个适配。
- 竞品参照：AgentBell（菜单栏）、MacNotch（AI 编码代理监控）、Droppy（AI 编码 HUD）。
- 差异化：**这是本报告里战略价值最高的一条。** 竞品清一色是单体应用，NotchCenter 可以用插件方式让社区各自认领一个 AI 工具的适配，天然形成「支持工具最全」的护城河；而本项目本身就有 OpenCode 用量插件的先例。

**㉒ 代码托管面板页（Dev Panel）** — *P1*
- 定位：指派给我的 PR / Issue / CI 状态一览，配审查队列。
- 依赖：`URLSession` 直连 GitHub/GitLab API，token 存 Keychain（**不引入新依赖**）。
- 可行性：**中门槛**（API 与鉴权工作量，无系统权限问题）。
- 竞品参照：MacNotch PR 审查队列、Raycast GitHub。
- 差异化：插件化后可支持多种托管平台，而非只绑 GitHub。

**㉓ 服务与包管理页（Services & Brew）** — *P1*
- 定位：把 launchd 服务（现有 Dsh/Calibre）与 Homebrew 包状态合成一个运维面板——服务启停 + 待升级列表 + 一键升级。
- 依赖：复用 `LaunchdControlKit` + `brew` CLI 调用。
- 可行性：**低门槛**（服务控制引擎已存在）。
- 竞品参照：Raycast Brew、Bartender 触发器。

**㉔ API 用量与成本页（Usage & Cost）** — *P1*
- 定位：把现有 OpenCode 用量卡扩展为多源面板——各家 AI 服务的配额、峰谷、当月花费。
- 依赖：复用 `OpenCodeUsagePlugin` 的抓取/缓存/峰谷时钟逻辑。
- 可行性：**低门槛**（逻辑与组件都已具备）。
- 竞品参照：FavTray 的 AI 成本追踪、MacNotch。
- 差异化：对重度 AI 用户是刚需，且能复用已有代码。

**㉕ 容器 / 虚拟化页** — *P2*｜Docker 容器列表与生命周期管理（调 `docker` CLI）；竞品 Raycast Docker。

### 4.6 健康与专注

**㉖ 控制中心开关页（Control Center）** — *P0*
- 定位：One Switch 式的系统开关抽屉——深色模式、防休眠、隐藏桌面图标、屏幕保护、AirPods 连接、勿扰等，一眼可扫、一点即切。
- 依赖：多数走公开路径（`defaults`、AppleScript、`NSWorkspace`），个别（勿扰/Focus、蓝牙连接）需 Shortcuts 或较重权限。
- 可行性：**中门槛**（单项成本低，但开关种类多、权限分散，需要逐项兜底）。
- 竞品参照：One Switch、MacNotch、Droppy。
- 差异化：现有 Caffeinate 已是其中一枚开关，页面化后把所有开关收进一处，符合「聚合」的一贯思路。

**㉗ 屏幕使用统计页（Screen Time）** — *P1*｜前台应用采样 + 分类图表 + 切换次数，纯本地 `NSWorkspace` 通知；竞品 MacNotch 独家。

**㉘ 护眼与数字健康页（Eye Break & Wellness）** — *P1*｜20-20-20 全屏休息提醒 + 久坐/喝水提醒 + 呼吸引导；覆盖窗口即可，**低门槛**；竞品 MacNotch、FavTray（并把护眼做成免费）。

**㉙ 习惯打卡页（Habits）** — *P1*｜连续天数 + 热力图；`StateStore` 即可；竞品 NotchBox。

### 4.7 通讯与会议

**㉚ 会议助手页（Meeting Assistant）** — *P1*｜下一场会议倒计时 + 一键加入（解析 Zoom/Meet/Teams 链接）+ 静音/摄像头快捷开关；`EventKit` + URL scheme；竞品 Meeter、Droppy、MacNotch。

**㉛ 通知镜像页** — **不建议**。需要读取其它应用通知，macOS 无公开 API，只能碰通知中心私有数据库，受 TCC/SIP 限制且稳定性极差——竞品是靠长期逆向堆出来的，与「私有 API 只在已验证接触面内使用」的项目纪律冲突。

**㉜ 聊天 / iMessage 页** — **不建议**。依赖私有 ChatKit 数据库，安全边界与合规风险高。

### 5.2 分档结论

- **P0（首批 8 个）**：音乐中心页、系统监控仪表盘页、剪贴板库页、日历与日程页、待办与提醒页、控制中心开关页、AI 编码助手监控页、天气页。
- **P1（第二批）**：摄像头镜子、今日时间轴、多计时器/世界时钟、API 用量与成本、护眼与数字健康、颜色拾取、屏幕使用统计、习惯打卡、会议助手、截图与 OCR、启动器、文件转换、电池与设备、服务与包管理、代码托管面板、隐私监控。
- **P2（探索）**：RSS 阅读、播客、文本片段、窗口管理、容器、网络与下载。
- **不做**：通知镜像、聊天/iMessage、终端（依赖冲突）、锁屏小组件（超出宿主边界）。

### 5.3 建议路线图（三步走）

**第一步：把形态打透（复用现有引擎，零新依赖）。**

先落地音乐中心页、系统监控仪表盘页、剪贴板库页这三个「现有抽屉块的深度视图」。它们不需要任何新框架或新权限，是验证「整页块到底好不好用」的最低成本试验田；同时顺手抽出「整页块开发模板」（分区骨架 + 自管滚动 + 空态/加载态 + 设置入口），降低后续页面的开发成本。这一步完成后应能回答一个关键问题：**用户是否真的会为「比抽屉卡更深一层的视图」而额外打开一个整页。**

**第二步：补齐竞品标配，建立基础盘。** 日历与日程页、待办与提醒页、天气页、控制中心开关页。这四页拿来即用、用户预期明确，是「从能用变成好用」的门槛项；日历与待办同源 EventKit，一次授权两页收益。

**第三步：用差异化筑墙。**

AI 编码助手监控页单独成一条线，配合活动摘要做「代理跑完提醒」；随后接 API 用量与成本页、代码托管面板页、服务与包管理页，把 NotchCenter 塑造成「开发者/AI 工作流的常驻面板」——这是竞品短期内最难追的方向，因为它们没有插件生态可以分摊适配成本。

一条贯穿三步的原则：**每加一个页面，都先问「它是否值得占用 9 页里的一页」。** 页数是稀缺资源，宁可少而精，也不要把抽屉变成翻不到底的 PPT。

## 6. 明确不做与高风险清单

| 项 | 原因 |
|---|---|
| 通知镜像 / 内联回复 | 无公开 API，需碰通知中心私有数据库，TCC/SIP 限制下不稳定且不合规 |
| iMessage / 聊天客户端 | 私有 ChatKit 数据库，安全边界与合规风险高 |
| 锁屏小组件 / Live Activities | 超出宿主「刘海抽屉」的能力边界，需要独立窗口体系 |
| 终端页 | 需要引入终端模拟器新依赖，与「不引入新 SPM 远程依赖」冲突 |
| 全局文本片段展开 | 需要全局键盘注入，权限重、稳定性差、易被安全软件拦截 |
| 浏览器下载进度 | 需要浏览器扩展配合，跨应用侵入性强 |

另外三条「容易被忽略但必须守」的纪律：

- **权限要诚实**：日历、提醒、摄像头、屏幕录制、辅助功能，每一项都必须有清晰的授权引导与「拒绝后仍可用」的降级路径，不能因为拿不到权限就整页报错。
- **隐私是卖点不是负担**：AI 监控页、剪贴板页、屏幕统计页都应明确「数据不出本机」，这条在本项目的 `StateStore` 本地持久化模型下天然成立，应当写进每个页面的说明里。
- **页面不豁免设计规范**：配色、圆角、排版、动效一律引用 `NotchTokens`，深色近黑半透明、白色层级、spring 动效的观感不能因为「整页空间大」而走样。
