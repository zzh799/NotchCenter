# Agent Note:提醒事项块大态改版——头部「计数在上 / 名称在下」+ 断点下调

status: implemented
date: 2026-09-20
deciders: zhouzihang

## Context(背景与约束)

需求：把「较长较宽」尺寸下的提醒事项块改成新参考图（用户提供 image2，卡 688×688px = 344×344pt，1pt = 2px）的样子：

- 标题名（「今天」）与事项计数（「3」）**显示在顶部**，计数在上、名称在下，左对齐堆叠；
- 列表项**从顶部往下排**，不再被头尾夹在中间居中，剩余留白沉到块底；
- 头部区带底部加一条实线，行间隔线改虚线；右上角标放大并对齐内容盒。

**当前为什么看不到这个版式（根因，非偏好）**：实测当前网格 `cell 75×75` / `spacing 12`，块内容高只取离散档 `75 / 162 / 249 / 336 / 423…`。`tallHeightThreshold` 是 360，于是只有 5 格高（423）才进大态；用户手上这块是 4×4 = **336×336**，恒落宽态——宽态版式正是"圆形徽章在左上、计数与名称沉底、列表居中"，与需求相反。4×2 = 336×162（现状截图）继续走宽态是符合预期的（它是横扁卡），不动。

已查证可直接复用/必须遵守的既有约束（本 note 不重复其"为什么"）：

- 三态双轴断点与探针同源推导的纪律 —— [`2026-09-20-reminders-block`](../implemented/2026-09-20-reminders-block.md) D3 / Consequences。
- 块内动作角标默认隐藏、悬停才浮出，**不单列 `BlockProbe`** —— [DESIGN.md §9](../../DESIGN.md) 与 [插件开发约定](../../agents/插件开发约定.md)。
- 插件本地样式常量收敛在 `RemindersPalette`，token 未覆盖的取值可留在插件并注明理由 —— 同 note D5 与 `RemindersPalette` 文件头。
- 抽屉强制深色、UI 走 `NotchTokens`，新增 token 需先改 DESIGN.md；**本方案不新增 `NotchTokens`**。

实测（对 image2 逐像素量取，pt，卡顶/左为 0，卡宽 344）：内容内边距 16；计数墨迹 21.5→44（≈31pt 字）；名称墨迹 52.5→66（≈16pt 字）；头部线 y 80→82，2pt，x 16→327.5（内容盒全宽）；右上圆钮 ⌀34，圆心 (310.75, 39.75)，右缘即内容盒右缘；行圆心 101.5 / 138 / 174.5（行距 36.5）；行间虚线 1pt，dash 2 / gap 1，x 42.5→327.5（左对齐标题、右到内容盒）；勾选圈 ⌀16.5、描边 1pt；圈→标题 10.5；重复图标 11。现状截图（4×2 = 336×162）实测行距 25、内边距 10，与代码一致——**两张图同为 1:1 点**，可逐值对照。

明确不做：卡片圆角与描边（宿主 `BlockCard` 壳，现 10pt，全库共用；image2 的 ≈20pt 属宿主改动，另开）、卡片底色与玻璃质感、行顺序（EventKit 返回序，见 D6）。

## Decision(决策)

### D1 断点：`tallHeightThreshold` 360 → 300

300 落在网格离散档 249（3 格）与 336（4 格）之间，效果是：4×4（336×336）及以上进大态；4×2（336×162）/ 4×3（336×249）保持宽态；宽度 < 300 的仍是窄态。参考中卡（368×290 横扁）仍落宽态，不破坏 D3 的原意。

用绝对 pt 而非"格数"或长宽比：格子尺寸是用户可改的设置，插件不能依赖它；长宽比规则会让 600×500 这种大块掉回宽态（底部带页脚），不可预测。

### D2 大态头部：计数在上、名称在下（左对齐）

`VStack(alignment: .leading, spacing: 0)`：计数 31pt semibold + 名称 16pt semibold。原实现是同一行"计数左 + 名称右"，与参考图不符。

### D3 大态区带与新增几何

| 项 | 宽态 / 窄态 | 大态（改后） | 原大态 |
|---|---|---|---|
| 内容内边距 | 10 | **16** | 10 |
| 顶部内容高 | 20 / 28 | **54** | 32 |
| 头部线 | 无 | **2pt**，在区带底边，x 16→w-16 | 无 |
| 名称行盒底 → 头部线间距 | — | **10** | — |
| 顶部区带高 | 40 / 48 | **82** | 52 |
| 行高 | 22 / 25 | **36.5** | 25 |
| 行标题字号 | 11 / 12 | **13.5** | 12 |
| 勾选圈 | 14 / 16 | **⌀16.5 · 描边 1pt** | ⌀16 · 1.2pt |
| 圈 → 标题间距 | 8 | **10.5** | 8 |
| 重复图标 | 10 | **11** | 10 |
| 行间隔线 | 无 / 1pt 实线 | **1pt 虚线 dash[2,1]** | 1pt 实线 |
| 行间隔线左端 | 行缩进 | **对齐标题起点**（+⌀ +间距） | 行缩进 |
| 右上角标 | ⌀22 · 距块边 6 | **⌀34 · 距块边 16**（对齐内容盒） | ⌀22 · 6 |

头部线颜色 white 0.10、行间虚线同色：**现有 `Hairline.divider`（0.045）在深色卡上等于看不见，达不到参考图"一条分隔"的效果**；`Hairline.drawerEdge`（0.09）接近但语义是"外描边"。两个值都放进 `RemindersPalette`（插件本地收敛点，已注明理由），**不新增 `NotchTokens`、不动 DESIGN.md**。

### D4 角标仍悬停浮出

参考图里 ⌀34 圆钮是可见的，但块内动作角标"默认隐藏"是 DESIGN.md §9 的硬约定，只放大直径与落位，**不改显隐契约**。大态顶部尾部预留 = 16 + 34 + 8 = 58pt，保证悬停浮出时不压住计数/名称。

### D5 不新增探针

头部线画在顶部区带内（区带底边），行间虚线随行滚动，二者都不产生新区带；`BlockSizeVerifier` 的越界/互不重叠判定不变。

## Alternatives considered(备选方案)

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 只改大态头部结构、不动断点 | 改动面最小 | 336×336 根本进不了大态，用户看不到任何变化——等于没做 | 否 |
| 加第四态（"方态"） | 三态语义不受影响 | 第四组区带 + 第四组探针 + 第四组单测；断点仍要选一个阈值，复杂度换不来新信息 | 否 |
| 断点按长宽比（h ≥ 0.9w） | 不依赖格子设置 | 600×500 会掉回宽态（页脚版式出现在大块上） | 否 |
| 断点按"格数 ≥ 4" | 与网格对齐 | 格子是用户可改设置，插件层拿不到也不该依赖 | 否 |
| 全部尺寸统一用 16 内边距 | 常量只剩一个 | 窄态 150 宽下左右各让 16，宽态页脚与徽章也要重排，超出本次需求 | 否（仅大态 16） |
| 头部线用 `Hairline.divider` 0.045 | 零新增常量 | 实测等于看不见，参考图的"分隔"语义丢失 | 否 |
| 角标常驻显示 | 与参考图一致 | 违反 DESIGN.md §9「块内动作角标默认隐藏」 | 否 |
| 行高取 36（圆整） | 无 .5 偏移 | 与实测 36.5 差 0.5pt/行，累积在 3 行上 1.5pt | 否（用 36.5） |
| 卡片圆角跟参考图改到 ≈20 | 更像参考图 | 圆角属宿主 `BlockCard` 壳，全库共用，改它等于动所有块 | 否 |

## Consequences(影响)

- `Plugins/RemindersPlugin/Sources/RemindersMetrics.swift`：阈值 360→300；新增大态常量；`RemindersLayout` 新增 `headerRuleHeight` / `rowDividerDashed` / `dividerLeadingInset` / `rowSpacing` / `repeatIconSize` / `cornerControlDiameter` / `cornerControlInset`；`padding`、`cornerControlRect(in:)` 按态取值。
- `RemindersBlockView.swift`：大态 `topZone` 改 VStack + 头部线；角标直径/内边距读版式。
- `RemindersRowView.swift`：行间隔线支持虚线与左端缩进；圈/标题/间距/图标读版式。
- `RemindersPalette.swift`：新增 `ruleStroke`（white 0.10）与 `rowRuleDash` [2,1]。
- `Tests/NotchCenterTests/RemindersMetricsTests.swift`：`breakpointsUseBothAxes` 里"900×359 = 宽态"失效（359 ≥ 300），改为断言 4×4（336×336）进大态、4×3（336×249）留宽态；`topContentAvoidsCornerControl` 与 `cornerControlSitsInsideTopBand` 需在新 ⌀34 下仍成立。
- 无 Kit 改动、无宿主改动、无本地化改动、无 `Plugin.plist` 改动（recommended 300×360 仍落大态）。
- 已知取舍：大态内边距 16 与其余态 10 并存，`padding` 成为按态取值——后续再调版式须确认改的是哪一档。
