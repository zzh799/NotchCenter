# Agent Note: 指针时钟块 `clock.analog`：等比表盘 + 点击打开时钟.app

status: implemented
date: 2026-09-20
deciders: zhouzihang

## Context(背景与约束)

需求：抽屉里放一个指针时钟组件，视觉复刻 macOS 桌面小部件那张时钟截图（圆盘 + 60 刻度 + 1–12 数字 + 时/分针），点击打开时钟.app。

**参考截图不是"深色卡片"**：它的灰是半透明材质叠在壁纸上（卡片 `#747E8D`、圆面 `#8A96A8`、数字 `#E9FCFF` 带蓝调，壁纸从圆角外透出）。因此"复刻"到近黑抽屉里必须重新解算配色——见决策 3。

截图实测（366×362 @2x，即 183×181pt；D = 表盘圆直径 = 290px）：

| 元素 | 实测 | 相对 D |
|---|---|---|
| 卡片 / 表盘圆 | 164×164pt / 直径 145pt | 0.884 |
| 刻度环 | 径向 r 129–140px，粗 2px | 0.4448–0.4828 |
| 刻度明暗 | 12 个整点位亮度 249（白）；48 个分位 155–182（灰） | — |
| 数字 1–12 | 环带中心 r 105px；cap 高 25px（em ≈ 34.3px）；竖笔画/字高 = 0.20 → **SF Rounded Bold**（Regular 仅 0.116） | 0.3621 / 0.118 |
| 指针 | **只有时/分针，无秒针**；分针 122px、时针 80px、宽 10px、圆头 | 0.4207 / 0.2759 / 0.0345 |
| 中心环 | 外径 19px、环宽 6px（中心是孔，非实心点） | 0.0655 / 0.0207 |
| 表盘渐变 | 上亮下暗（顶 194 → 底 115），光从上来 | — |

硬约束来自既有门禁与契约：

- 官方抽屉块必须声明三档 `min/max/recommendedSize` 与 `probes`（[插件开发指南](../../插件开发指南.md) §3），`BlockMinSizeVerificationTests` 按 `Plugins/` 清单逐一校验。
- 抽屉强制深色、UI 走 `NotchTokens`（[插件开发约定](../../agents/插件开发约定.md)），不推荐内联字面量。
- `blockPopoverTrigger(onTap:onLongPress:)` 的 `onLongPress` 是**必填**参数，点击必须走该管线的 `DragGesture`（裸 `TapGesture` 真机不回调）。
- 窗口温存契约：收起态视图不卸载，跨分刷新不能只靠 `.onAppear`/`.onDisappear`。

不在范围：秒针（截图没有）、数字钟形态、12/24 小时切换、世界时钟/时区换算、实例设置、快捷按钮、紧凑块。

## Decision(决策)

1. **块身份**：`Plugins/ClockPlugin`，块 id `clock.analog`，`kind: .drawer`，三档固定 `150×120`（= 默认格 150×120 下的 1×1），`symbolName: "clock"`。固定档的收益是版式可穷举；代价是用户不能拖大——但**等比自适应无论如何都要做**（宿主允许用户改格子尺寸 20–280，同一块 1×1 的物理尺寸随格漂移），所以这条只约束"占多少"，不减少任何实现工作。
2. **几何全部是 D 的比例**：`ClockFaceMetrics` 的常量表即上表的比值，视图与探针同源取用。表盘内切于内容盒短边、居中——所以**表盘在任意物理尺寸下都是同一张脸的缩放**，没有版式分支，也没有最小尺寸下的挤压（截图那张脸的比例在 104pt 和 220pt 上都成立）。
3. **深色适配而非照搬浅灰**（截图配色不可移植）：保结构、丢数值。
   - 圆面 = 白色 `0.07 → 0.045` 纵向渐变（保留截图"卡片 → 圆面"两级层次；渐变差 2.5pp，符合"克制的白色层级"上限）。**不照搬 #8A96A8**——不透明浅灰在近黑抽屉里是刺眼亮块，且违反 DESIGN.md §1。
   - 刻度：整点位与数字/指针/中心环共用 `Foreground.body`（截图实测这些元素同为一种白，249 vs 246 无差异）；分位刻度用本地常量 `0.32`。
   - **分位刻度的 alpha 是层级移植不是数值移植**：截图分位刻度只比面板亮 13/255（中灰底上可辨），近黑底上同等绝对差不可见（魏伯灵敏度差异），照搬 0.14 会得到一圈看不见的脏点。层级关系（整点白 / 分位明显次于白 / 数字与指针同白）是移植目标。
4. **点击 = 打开时钟.app，长按与点击同义**：`onTap` 与 `onLongPress` 都调 `ClockAppLauncher.open()`。照 bundle id `com.apple.clock` 解析（本机 macOS 15.7.5 确认存在 `/System/Applications/Clock.app`），失败退回标准路径——**时钟.app 未注册任何 URL scheme**（`CFBundleURLTypes` 不存在），写不出日历那种 `ical://` 式的深链兜底。
   - 为什么长按不留空：管线在按满 0.2s 时置 `longPressFired`，`BlockTapClassifier.isTap` 据此返回 false，**松手不会再触发 onTap**——空实现等于"按久一点就什么都不发生"，比没有长按更糟。同先例：`ScratchpadPlugin`（onTap/onLongPress 同回调）。
5. **每分钟对齐刷新**：只画时/分针，分针每分钟跳一格，秒级定时器是纯浪费。块视图持 `@State now`，`.task` 睡到下一个整分再取时间；`\.isDrawerPresented` 变真时**幂等**重校准（覆盖睡眠唤醒/定时器失准），不吃 `.onAppear` 语义。
6. **无状态、无浮窗、无快捷按钮**：不写 `stateStore`、无 `settingsView`、无活动摘要、无紧凑块。纯函数式渲染（`ClockFaceSnapshot`），多实例天然一致。
7. **探针只声明一个**：表盘是内切圆，唯一可能越界的元素是它的外接矩形；刻度/数字/指针按几何构造全在该圆内（`numeralRadius + cap/2 ≈ 0.405D < tickInnerRadius 0.4448D < 0.5D` 有测试兜住）。照指南"整面自适应的容器声明一个内容区探针即可"。

## Alternatives considered(备选方案)

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 尺寸声明成区间（150×120 → 300×240） | 用户可按需放大表盘 | 等比比例已经支持任意尺寸，区别只在"占多少抽屉"；放开上限等于让一个纯装饰块吃掉 2×2 | 否（用户选定固定 1×1） |
| 固定 2×2（300×240） | 最接近截图那块桌面小部件的手感 | 一次吃掉半页横向空间；最小格（75×60）下换算跳到 4×4 | 否（用户选定） |
| 照搬截图的浅灰圆面 | 与截图逐像素一致 | 近黑抽屉里的刺眼亮块，违反 DESIGN.md §1「深色为主、克制的白色层级」，且与 `BlockCard` 发丝边打架 | 否（用户选定深色） |
| 不画圆面，刻度数字直接落卡片上 | 最少嵌套、最"贴近刘海" | 丢掉截图"圆盘浮在卡片上"的层次感，视觉上变成"卡片上飘着数字" | 否（用户选定保留圆面） |
| 长按弹浮窗（数字时间+日期+时区） | 与 calendar.month 同构，且是"点击开 app"的唯一可发现点 | 多一个面板与一套文案；用户明确不要 | 否 |
| 长按空实现 | 零代码 | **吃点击**：按满 0.2s 后松手不触发 onTap，用户表现为"点了没反应" | 否 |
| 整卡包一层 SwiftUI `Button` 绕开管线 | 语义上真的没有长按手势 | 丢按压反馈与 hover 联动，偏离既有唯一可靠的点击管线（裸 TapGesture 真机不回调的结论） | 否 |
| 加一根秒针 | 更像真钟 | 截图没有；且强制秒级重绘（每分钟 1 次 → 每秒 1 次），与"吝啬唤醒"的取舍相悖 | 否 |
| 数字用 `NotchTokens.Text.system(size:)` 的默认设计（SF Pro） | 少一个参数 | 与截图不符：竖笔画/字高实测 0.20，落在 SF Rounded Bold（0.203）上，SF Pro Regular 只有 0.116 | 否（rounded + bold） |

## Consequences(影响)

- 新增 `Plugins/ClockPlugin/`（Plugin.plist / README / Sources / Resources），Project.swift 与 build.sh 自动发现，无需改清单；`Tests/NotchCenterTests/BlockMinSizeVerificationTests.swift` 的 `officialBlocks` 与 `LocalizationTests` 的 `modules` + plist 双语元数据用例必须同步登记。
- 无 Kit / 宿主 API 改动，无新 token（复用 `Foreground.body`、`Radius.card`、`Text.system`），本插件本地新增两个视觉常量（`ClockFacePalette.faceTop/faceBottom/tickMinor`）并注明豁免理由。
- 本地化新增 3 个键，en 与 zh-Hans 键位一致。
- 纯逻辑（指针角度、整分刷新、比例几何）落成可测函数，`ClockFaceGeometryTests` 覆盖：16:26:20 → 133.17°/158.0°、整点与 11:59:30 边界、整分等待秒数、150×120 与 300×240 的等比、数字环与刻度环不重叠、探针矩形落在 minSize 盒内。
- 已知取舍：分针每分钟**跳变**而非连续扫动（截图无秒针，跳变即 Apple 小部件的行为）；中心环是环不是实心点（截图实测中心是孔）。
- 与相邻块的按压反馈档位未对齐：本块不传 `pressFeedback`，沿用默认 `standard`，与同为"整卡即按钮"的 `calendar.month` 保持一致；Kit 为这一语义另备了 `emphasized` 档，两块的统一是独立议题。
