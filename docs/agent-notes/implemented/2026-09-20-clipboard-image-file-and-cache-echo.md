# Agent Note: 图片文件归为图片条目 + 拦掉缓存目录回写

## Context(背景与约束)

用户报了两个 bug，取证后确认是两件独立的事（证据见下），但都指向同一段代码：`SystemClipboardReader.readPayload()` 的归类优先级。

**bug 1 的取证。** 插件落盘历史里，每次复制图片都留下两条记录、相差 2.02 秒，第二条指向 `~/Library/Caches/WeType/dsclp/<epoch>.png`。为了拿到成因而不是结果，新写了 `Experiments/ClipboardPasteboardProbe/`（独立单文件探针，不参与 Tuist 构建），复现结果：

- 写入剪贴板后 `changeCount = 524`；**1.802 秒后变成 526**——跳了 2，说明回写者连写两次，只是我们采样太疏只看到净结果。
- 回写后的类型表**只剩 `public.file-url`**，图像数据（`public.png` / `public.tiff`）全部消失，fileURL 指向输入法自己的缓存副本。回写者不是同一次复制的第二步，而是**另一个进程**（微信输入法的剪贴板同步）。
- 缓存副本与原图经 `compare` 模式比对：两者都是 712×448 PNG，但字节 104218 → 69601，**连"降采样后取哈希"的像素指纹也不同**（`25e69b3c…` vs `ee900975…`，输入法重编码时改了像素或色彩配置）。

这条观测**证伪了本来的修法猜想**：我原以为"把图片文件也归成图片条目、按内容哈希去重"能顺带把重复记录吸收掉。既然回写者重编码过，任何基于内容的身份都救不了它；同时"加长去抖窗口"也不成立——回写发生在 1.8–2.0 秒后，而把去抖窗口拉到 2 秒会吞掉用户真实的连续两次复制。**只能在来源处拦。**

**bug 2 是决策反转。** [2026-09-20-clipboard-media-types](2026-09-20-clipboard-media-types.md) 的 D3 刻意把 `.fileURL` 排在图像数据之前，理由是"Finder 复制一张图片时用户意图是'这个文件'"。用户的实际反馈是否定的：复制一张 PNG 得到的是一个**文件名条目**（有时还是 `1789847147206.png` 这种临时名），既没有预览也认不出是什么。用户要的是图片。

**不做**（out of scope）：把系统临时目录（`/var/folders/…/T/`）也纳入回写拦截（没有证据说明那里会出现同类回写，而"程序导出到临时文件再复制"是真实用法，误伤代价比收益大）；多选文件里的图片单独拆条目（见 D1）。

## Decision(决策)

**一句话：单个图片文件读它的字节当图像载荷（不复制原文件、只读一次）；路径落在 `~/Library/Caches/` 下的文件引用一律不收。**

**D1 — 单个文件 + 文件类型是图片 → 图像载荷；多选或非图片 → 文件引用。** 加"单个"这个限定不是偷懒：一次复制的原子单位是那一组（D2 的聚合粒度），多选里混着图片与 PDF 时，按类型拆条目会直接破坏"点击写回整组"的契约。单文件是覆盖用户实际场景（复制一张截图 / 一张图）的最小面。

**D2 — 读**文件字节**，不用剪贴板上现成的图像数据。** Finder 复制图片文件时会附带 `public.tiff`，那可能是**文件图标**而不是图像本身；文件字节才是权威内容。代价是每次复制图片文件都要读一次磁盘（上限 `maxMediaSingleBytes`），换来的是内容正确。

**D3 — 超过媒体单条上限的图片文件退回文件引用，不整个丢弃。** 复制一张 50MB 的 PNG 时，若按图片处理会被上限拒收、用户连"我复制过这个文件"都看不到；退回文件条目至少保留了可用的引用。这是"上限拒收"与"条目整个消失"之间唯一诚实的取舍。

**D4 — 路径落在 `~/Library/Caches/` 下的文件引用不收。** 判据只有一条，不用启发式打分：该目录的系统语义就是"程序自建、可随时删除、不是用户资产"，用户不会从那里复制文件——出现在剪贴板上的缓存路径必然是某个进程自己回写的中间产物。落点 `ClipboardFilePayloadPolicy.isDisposableCachePath(_:cachesRoot:)`，`cachesRoot` 可注入以便单测。

**D5 — "文件条目只持有路径引用"这条契约不变，变的是"什么算文件条目"。** [插件开发约定](../../agents/插件开发约定.md) 讲的是**文件条目**不复制用户原文件；图片条目一直都存字节（载荷来自剪贴板数据还是文件，不改变这一性质）。所以本次没有破坏那条红线，只是把"图片文件"从文件条目挪到了图片条目。**但要认一个后果**：现在复制图片文件会把它的字节快照进 `Media/`，快照不跟随原文件的后续修改，删除原文件也不会释放这份快照。

**D6 — 判据做成纯函数以便单测。** `SystemClipboardReader` 本身碰真实 `NSPasteboard`（测试红线不许碰），所以"哪些文件算图片""哪些路径可丢弃"两条规则抽成 `ClipboardFilePayloadPolicy`，只吃路径、只碰 `FileManager` 与 `UTType`，可直接单测。

## Alternatives considered(备选方案)

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A. 缓存目录拦截 + 图片文件归图片条目（本决策） | 两条 bug 一起解决；判据有系统语义支撑、可解释、可单测 | 真把用户文件放 Caches 下的程序会被误伤（那种用法本身违背 Caches 语义） | **采用** |
| B. 内容等价去重（内容哈希 / 像素指纹）吸收回写 | 不用猜来源，语义最干净 | **实测证伪**：输入法重编码过，字节与像素指纹都不同 | **否决** |
| C. 加长去抖窗口（把 2 秒内的变化合并成一条） | 一处改动覆盖所有"分步写" | 回写在 1.8–2.0 秒后，窗口得拉到 2 秒，会吞掉用户真实的连续两次复制；且回写是**覆盖**而非追加，合并策略也不对 | **否决** |
| D. 黑名单 `/var/folders` 系统临时目录 | 覆盖面更大 | 没有实测证据；"程序导出到临时文件再复制"是真实用法，误伤代价高于收益 | **否决** |
| E. 保留 D3 的 fileURL 优先，只在 UI 上给图片文件加缩略图 | 不动归类语义 | 用户明确要求"应是图片"；且文件条目没有内容哈希，回写拦截也救不了重复记录 | **否决** |
| F. 图片条目同时保留 fileURL，写回时两种表示都给 | 往 Finder 贴图片也能用 | 回到 `2026-09-20-clipboard-media-types` 的 D7/G2：接收方若优先取 fileURL 会把"贴图"变成"发文件"，同一剪贴板在不同 App 里行为不一致 | **否决** |
| G. 多选文件里把图片拆出来单独成条 | 更"精确" | 破坏"一次复制 = 一条"的聚合契约与整组写回 | **否决** |

## Consequences(影响)

- **改动落点**：`ClipboardHistoryStore.swift`（新增 `ClipboardFilePayloadPolicy`；`SystemClipboardReader.readPayload()` 的两处分支）、`ClipboardFilePayloadPolicy` 的判据与 `ClipboardHistoryLogic` 无关（归类仍由"有没有 imageData"决定，逻辑层不动）、`Experiments/ClipboardPasteboardProbe/`（**新增**：`watch` / `copy` / `compare` 三个模式的取证探针，本决策的证据来源，后续遇到"剪贴板被谁改了"的问题可直接复用）、`README.md`（"记录规则 > 文件"两节要改：图片文件归图片条目、往 Finder 贴图片的行为变化）、双语 `Localizable.strings`（若文案需调整）。
- **用户可见的行为变化**：复制一个图片文件不再得到"文件名"条目，而是带预览的图片条目；代价是**往 Finder 里 `Cmd+V` 贴这条不再有反应**（图片条目只写图像数据，D7 未变）——想要文件请直接拖原文件。这一条必须在 README 里写明。
- **回归面**：非图片文件（PDF / zip / 代码）仍走文件条目，多选仍聚合成一条；`transient` 判定不变；媒体预算与落盘路径不变。**新引入的一次磁盘读**（复制图片文件时）受 `maxMediaSingleBytes` 兜底。
- **未覆盖**：其它输入法 / 剪贴板同步工具若把缓存写到别处（如 `/var/folders`），本决策拦不到——判据是目录语义，不是行为识别。真出现再说，`ClipboardPasteboardProbe` 是现成的取证工具。
- **测试**：`ClipboardFilePayloadPolicy` 的判据按注入的 `cachesRoot` 单测（不必依赖真实 `~/Library/Caches`）；图片 UTI 判定用临时文件（`.png` / `.pdf` / 无扩展名）；"图片文件 → 图片条目"的端到端路径**碰不到**（`readPayload` 要真实剪贴板），只能靠真机核对——这是本决策最大的测试盲区。
